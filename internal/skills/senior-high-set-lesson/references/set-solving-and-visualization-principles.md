# 集合题求解与可视化原则

## 数学推导

- 先写定义或已知条件，再写等价变形，最后写题目所求的集合、参数或数量。
- `because` 只承载已知或已证事实，`therefore` 只承载由上一事实推出的结论。不要写“∵解方程 ∴答案”一类省略中间对象的句子。
- 分类讨论必须写出分类依据。例如二次方程含参时先分最高次系数是否为零；元素属于有限集合时分别令它等于各候选元素。
- 解集必须区分数、数对和集合：方程组的解是有序数对 `(x,y)`，解集是 `{(x,y)}`。
- 使用集合互异性筛掉令元素重复的参数值；使用无序性时说明排列不改变集合。

### 含参区间与分类讨论

- 先判断含参区间是否为空。对开区间 \((l,r)\)，非空条件是严格的 \(l<r\)；\(l=r\) 已属于空集情形，不能混入非空分支。
- 顶层先分“空集 / 非空集”。非空集若还需讨论位于另一集合左侧或右侧，应把左右位置作为非空分支的两个子情况，并逐一验证是否有解。
- 表格必须显式写全每个分支的前提。例如“非空且在左侧”同时写出非空条件和右端点位置条件，不能只写其中一个。
- 各分支互斥时，最终参数范围取并集；解析中明确写出并集等式，不只写“合并得”。
- 包含、相离等结论同时检查端点开闭。端点相等是否允许，应由两侧集合是否取端点决定。

## 表示方法

- 列举法：有限且规模可控时逐一写出所有元素，去重且不遗漏。
- 描述法：写清代表元素、取值范围和共同性质，不能混淆横纵坐标代表的集合。
- 区间法：先求连续实数范围，再决定端点开闭；无穷端一律用圆括号。
- Venn 图法：先确定全集与每个集合，再翻译阴影的包含、排除和交叠关系。

## 可视化选择

- 小规模有限情况、参数候选、关系真值、有序数对枚举：使用语义化表格。
- 不等式解集、区间并集、孤立点与连续区间：使用数轴，明确开闭端点。
- 集合差、交并、包含与计数：使用 Venn 图，并确保阴影严格裁剪在目标集合内部。
- 纯方程求解或符号化简：不画图。
- 图形必须参与证明；不要重复展示与推导无关的装饰图。

### 可视化必须对应推理层级

- 一个对象占一条数轴：当题目同时涉及集合 \(A\)、集合 \(B\) 和最终集合或参数范围时，优先用三条对齐数轴分别表示它们；不要把离散点、区间和参数结论叠在同一条轴上造成角色混淆。
- 参数题的最后一条轴是参数轴，标出临界值、开闭点和射线方向；不要只在集合轴下方放一句结论文字。
- 非空区间位于另一集合左侧、右侧的两个分支若都有教学意义，分别使用数轴；无解分支也要画出导致矛盾的端点要求或在表格中明确标记“条件矛盾”。
- 分类表先展示顶层情况，再展示子情况；必要时拆成连续步骤或使用分组标题，避免视觉上把不同层级并列。
- Venn 图在阴影区域内或邻近位置标注目标集合表达式，例如 \(B\\setminus A\) 或 \(C_UA\)，不要只依赖图注。
- SVG 在手机宽度下必须保持标签完整。检查左侧行标签、分数、端点文字和结论是否裁切或重叠；必要时移动标签、换行或增加 viewBox 留白。

## 内容忠实度与符号渲染

- 知识导图、教材小标题和练习分组只复现印刷材料中存在的层级。不要自行增加“符号辨析”“关系辨析”“综合提升”等标题。
- 不在专题引言中加入“后续补齐”“待发布”等制作状态说明；待补状态只由模块状态表达。
- 条件之间使用自然语言“且”“或”或受支持的结构化数学符号，不用反斜杠充当分隔符。
- 发布前搜索页面可见文本中的 `\\setminus`、`\\subsetneq`、`\\text` 等原始 TeX 泄漏；数学命令必须经过共享渲染器或改用已支持的 Unicode/结构化表达。

## 反馈驱动的回归闭环

- 浏览器批注先定位到 lesson source、topic source、共享编译器或运行时中的权威来源，不直接修改生成 HTML。
- 每个数学反馈同时完成三件事：修正结论或前提、补齐解释链、添加能捕获该错误的回归断言。
- 共享 SVG 或运行时视觉变更后提升资源版本号，避免浏览器继续使用旧缓存。
- 详情页逐页检查答案条、公式、表格和图形；聚合页检查题目顺序、在线判题、提示和解析链接。桌面与手机都检查页面横向溢出，并对关键图形截图复核。

## 在线答案

- 解析页的原题卡必须复用公共 answer-chip 位置展示最终答案；选择题显示选项字母，填空题显示最终结果，多问题按原题序号列出。
- 原题卡答案必须与聚合页 answerSchema 共用同一权威数据，不另抄一份答案，避免在线判题答案与解析页答案发生漂移。
- 聚合练习页默认不展示答案；学生点击“查看解析”进入详情页后才展示。
- 答案条只给最终结论，完整数学推导仍放在下方步骤区。

- 选择题使用 `single-choice`，序号选项使用 `choiceStyle: ordinal`。
- 单个数学表达式使用 `exact-expression` 或更具体的结构化 schema，并配置题目需要的符号键盘。
- 多个独立小问使用 `multipart-exact` 和 `layout: per-part`，每个小问独立提示、输入和校验。
- 关系填空优先把输入位嵌入题干；不要让学生在一个大文本框中重新抄写全部关系。
- 自然语言答案允许若干经过人工审核的等价表述；不要用关键词包含关系冒充数学语义判断。
