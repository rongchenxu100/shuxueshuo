# 原题目标与答案转换

同一数学问题可以问值域、最值、最值组成的算式，或者判断某个候选条件是否成立。求解方法负责给出经过独立验证的完整结果；答案转换负责按原题要求使用这个结果。转换不新增数学条件，也不能扩大求解器的适用范围。

## 三个独立部分

1. **求解任务**：原函数、原条件、输入范围以及要计算的集合。由现有题型识别、方法选择、执行和独立验证处理。
2. **回答要求**：用 `answer_request` 保存原题提问。代码将其编译为有顺序和依赖关系的转换计划；模型不提供执行计划或计算结果。
3. **原题作答**：转换结果按集合、数值或布尔值匹配原题选项。未找到唯一、可验证匹配时，不猜测标签。

新描述首先接入具体函数的 `find_range.object` 入口。编译和答案闭合共用同一准入检查：只有此入口可以携带 `answer_request`，其他 goal kind 携带该字段时拒绝处理，不能覆盖原目标。历史 `find_extrema_expression` 与 `select_range_domain` 保留兼容，通过适配器使用相同转换操作。求解算法和转换引擎不依赖题号或具体系数。

## 回答要求

公开契约见 `internal/schemas/graph-answer-request-v1.schema.json`，由 `validate_request` 与 `compile_plan` 校验和编译，仅包含下表前四种请求。

| kind | 含义 | 转换操作 |
| --- | --- | --- |
| identity | 返回完整集合；普通值域题可省略 | return_set |
| extremum | 最小值、最大值，或原题明确要求的上下确界 | extract_quantity |
| expression | 从结果提取命名量，再计算原题算式 | extract_quantity → evaluate_expression |
| compare_set | 判断完整结果是否等于／不等于题给集合 | compare_set |
| select（内部适配） | 逐项验证候选输入后，按成立／不成立筛选 | compare_candidates → select_truth |

例：同一个函数求最大、最小值的和。最大值、最小值只是原题的角色声明，不作为函数的参数写入事实。

```json
{
  "kind": "find_range",
  "object": "f",
  "answer_request": {
    "kind": "expression",
    "bindings": [
      {"symbol": "a", "quantity": "maximum"},
      {"symbol": "b", "quantity": "minimum"}
    ],
    "expression": "a+b"
  }
}
```

改问差、积、商只改变 `expression`；改问最大值用 `{"kind":"extremum","quantity":"maximum"}`。这些变化不会更换函数求值域的方法。集合比较保留题给集合，例如 `{"kind":"compare_set","relation":"equal","expected":"[1,5]"}`。

“最大值与最小值的和”等无字母问法，可用内部别名绑定这两个量。来源检查必须确认角色、运算及顺序；未覆盖的自然语言表述应报告来源绑定不足，不推测含义。这个接口不是任意自然语言问句的自动解释器。

## 候选条件

第 5 题的适配器把各个端点组合绑定为独立求解输入，仍由 M3 求各区间的完整值域。通用转换层接收有原标签的结果列表，逐项与题给集合比较，再依据题目选择“成立”还是“不成立”。顺序、标签、选项原文和单选／多选要求均保留。未知、缺失或无法验证的候选结果不能按“不成立”处理。

当前候选输入适配器仍限定二次函数的区间定义域。其他题型要接入时，需要实现其候选条件到合法求解任务的绑定和验证；可以复用后续比较、筛选及作答，不必修改这些转换操作。

`select` 是 `select_range_domain` 适配器生成的内部描述，由独立入口 `compile_candidate_plan` 校验和编译，不能写进公开的 `answer_request`。其结果仍按 `select_range_domain` 返回原选项标签，不生成 `derived_answer`；展示沿用逐项核对与选项收束卡片。若后续开放新的候选题入口，必须同时定义候选结果、答案和卡片契约。

## 验证与展示

- 独立验证覆盖完整集合，不能只凭边界或抽样认定相等。
- 最大／最小值必须属于集合；上下确界允许端点取不到，两者不可混用。所需量不存在时，即使算式可以形式消去该符号，也不能返回数值。
- 算术只接受有界的精确运算。除零、未知符号、过深表达式以及不支持的操作失败关闭。
- 转换计划由原请求重新编译；答案校验从已验证结果重新执行，不信任传入的计划、步骤证据或展示文字。
- 通用问法的交互卡由操作记录生成，显示原函数、已验证结果、原题所需量和所求式；原题答案匹配在转换后进行。未支持的操作会报错，不能回退显示为完整值域。
- 历史题目保留既有答案契约；统一请求输出 `derived_answer`，区分集合、数值、判断及不存在等状态。

核心入口为 `problem_understanding/answer_requests.py` 和 `graph_lesson/stage_three/answer_conversion.py`。引擎只消费精确集合或带标签的候选结果；函数族的支持判断继续留在各求解器中。
