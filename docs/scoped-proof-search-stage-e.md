# 阶段 E：链路迁移

日期：2026-09-28。实施依据为 [Scope 事实复用与分层证明搜索设计](scoped-proof-search-architecture.md)。

## 入口与兼容边界

新增显式运行协议 `RuntimeOrchestrator(proof_protocol="scoped-facts/v2")`，在创建事务上下文之前固定；检查点记录 `condition_protocol`，恢复时必须一致。现有默认仍为 `bound-conditions/v1`，生产默认切换、旧搜索清理由阶段 F 处理。本阶段没有真实 LLM 调用、生产发布或浏览器检查。

新协议接入 M01、M07、M08、M11、M12、M13 的真实执行路径，禁止失败后静默调用旧搜索。旧录制计划按旧前提集执行，旧证书直接交给 checker 回放；不会因为新协议可见更多原条件而改写历史证据。

本阶段的自动授权适配器面向已注册的单 Method 调用以及有认证 `extremum_target` 的 authoring 路线。v2 按 `method_proof_backends.py` 的显式后端清单分流：不使用 bounded-real 证明内核的几何、二次函数等 Method 继续自身验证，允许纯此类 Method 的多 invocation 调用，不建立证明授权或发布共享事实。涉及证明内核的调用仍限单 invocation，缺少授权 overlay 时拒绝；未知后端也拒绝，不静默进入旧搜索。注册表穷举测试要求新增 Method 明确登记后端。M01 必须能从准确 StateVersion 的 owner 找到唯一可见目标；来源含糊时拒绝。一个事务事实库当前绑定一个原始 source context；共享相同原始条件的目标可以复用，原始条件集合不同的目标不能悄悄合并进该库。这不是任意 Family、任意复合调用的默认启用。

## 调用授权、共享证明与事务

`runtime/method_proof_integration.py` 负责代数 Method 的适配，通用事务模块只调用适配入口，不知道题号和数学规则 ID。

- 调用授权来自已编译的输入读取、准确目标对象及 ProblemIR 原条件；不接受 LLM 自报的 Scope 或证据声明作为授权。
- 通过 `MethodProofSession` 向内核提供当前调用可见且生产证书已回放的片段。搜索命中片段时，按实际使用的前提身份重建 DAG，并逐节点交给 checker；没有把派生结论改成无条件 `given`。
- 单次搜索内部仅记录成功证明实际使用的共享片段；搜索候选失败会恢复节点、编号、证明缓存和读取标记，算术费用不退款。Method 层保守累计每个已成功子请求的读取，即使上层应用候选后来被放弃，也保留其依赖，保证本调用局部证明缓存继续有效。每个 fact ID 在本调用只写一次 reuse 记录。该集合可能大于最终应用的最小依赖集，但不会漏掉依赖；Method 失败时整个私有 overlay 不提交。
- M01 前提匹配核对完整的变量名与符号身份绑定，多个合法来源按 producer/source/fact ID 稳定选择。M01 发布定义域/恒等证明；M07/M08/M11/M12 通过各自的既有证据适配器重放后发布。取等要求仍单独保存，M13 的见证赋值不发布成全局事实。
- Retry 恢复先在私有上下文恢复经验证的调用输出，再按已提交前缀重新建立调用授权并恢复事实。Scope、调用指纹、输出 hash、依赖和协议一起核对，失败不提交私有上下文。空提交检查点在协议及空 manifest 校验后允许恢复；非空路径不再在循环结束后重复恢复完整前缀。逐次重建前缀仍有平方级重放成本：q30 从 20 次提交重放降为 15 次；增量追加另行优化。

M07→M08 验收检查实际共享读取和 producer 依赖；M08 的复用记录及其依赖证明不含 AM-GM 规则。q30 验收检查 `M01 → M11 → M12 → M11 → M13` 的四条准确消费边和三条累计取等要求。

## 搜索与独立检查

新会话只复用阶段 D 的策略调度和现有 checker 规则。原有 Method-local 前提保留自己的语义与来源，不将待检取等条件或分支假设发布成 Scope 事实。

检索按目标建立局部视图，以 4、8、当前 Method 完整有效前提集逐级扩大。已有同方向完整界优先于无关等式基；共享片段在子目标精确命中时也可参与。每轮分配同一总账的剩余额度；成功后在准确的原 Method 上下文重建、独立回放证书。

迁移使用 `layered-method-search/v1`：候选局部额度为 attempts 256、reductions 256、nodes 512，以容纳换元定义域与连续求界的复合子目标。未提高 Method 的全局 ProofLimits 或 65536 算术额度，阶段 D 的默认 policy 未改变。真实总账耗尽继续上抛，不伪装成应用契约错误。

本阶段还补充两项搜索构造：

1. 相同左式、不同根式写法的同方向界，先证明差值恒等，再用既有 `relation_transport` 规则传递；例如 `1/(2√3−3)=1+2√3/3`。错误常数仍拒绝。
2. 同一总账内缓存准确常数 AST 与有效 limits 对应的隔离证书（最多 64 项），避免候选重复消耗根式细分额度；返回深拷贝。该缓存只用于搜索构造，独立 checker 仍重新核对，不能替代验证。

规则包及规则 hash 未变；旧搜索仍保留供旧协议使用，未作新路径的回退。M13 外层见证入口使用 checker Environment 构建证书，其内部数学请求进入新会话，见证重放不调用搜索。此构造调整也作用于 v1：嵌套见证重放费用计入构造预算，审查实测 q30 的 attempts/nodes 不变，refinements 从 6 变为 9（上限 128）；因此不宣称 v1 的所有预算计数逐项不变。

## 本次应用与教学

M11 新证据保存 `verified-amgm-application/v1`：准确 source/bound、target hash、调用输入指纹、生产调用、Scope、committed manifest、提交行来源、参与项、显式局部 AM-GM 根、完整表达式替换证明、取等关系及 application ID。

参与项候选只来自本次提交的关系及准确输入表达式；选择能解释完整转换的规范候选，由独立 checker 验证局部规则及其作用。本次应用根是明确构造的局部规则根，不从整个依赖 DAG 中统计 AM-GM 节点。正性子证明或共享片段含旧 AM-GM，不增加本次应用次数；只有旧界而没有新转换也不能冒充新应用。局部倒数下界和定和乘积上界都使用该接口，整体倒数路线保存其内层应用证据。

新协议发布时核对应用绑定与调用授权；回放核对记录、规则根及完整效果。教学投影读取这份应用记录生成局部关系，不扫描搜索内部节点。新记录通过 `local_rule_origin` 指向出现参与项的具体提交行，优先选不等式行；若只来自准确输入，则明确记作 source_expression。规则根由 Method 构造，此字段记录参与项来源，不把整段提交都归为局部规则来源。v2 发布及事实恢复强制要求 `local_rule_origin`，具体内容继续由应用 checker 重建比对；删除字段并重算 application ID 不能降级绕过发布。缺少此字段的旧应用记录仅保留原独立回放与教学兼容。只有旧证据仍使用兼容投影分支。

q30 的七个学生步骤仍由已验证 Method 证据编排：观察、合并、局部倒数方向、AM-GM、平方非负、再次 AM-GM、联立取等。辅助事实提交不增加教学动作。q29 整体倒数与 q01 乘积上界也从真实执行证据完成 HTML 编译。

## M01 条件协议

新协议中，准确目标所属可见 Scope 的认证原条件自动可用。`conditions` 保持原参数形式，显式绑定作为提示，不限制代码可用的原条件；省略、空、部分和完整绑定均覆盖。未知引用仍由绑定层拒绝。

若仍无法证明分母非零，反馈为 `domain_unproved` / `repair_domain_proof`，指出未证条件，不再要求重复绑定已知原条件。旧协议仍使用 `bind_domain_conditions` 及旧前提集。Method spec、生成快照及 Family 提示词同步区分两种协议。

1. 去掉 v2 前缀恢复结束后的重复完整恢复；新增真实 q30 恢复调用计数断言。暂不引入新的增量恢复 API，平方级前缀重放的剩余成本已明确记录。

5. 以“成功子请求依赖的保守并集”描述 Method 读取，按 fact ID 去重；保留已经成功的子证明依赖以维持局部缓存正确性。
