# 图谱交互课程阶段②实现计划：特征检查表判型与 D1、D2

阶段②读取已验收题意与特征，按注册的识别契约判型。唯一命中由程序确认，多命中由 LLM 选择；零命中返回暂不支持。识别、准入与数学执行分别验证，题型节点存在不表示能力已开放。

## 1. 目标与边界

程序用特征检查表缩小题型范围；唯一命中则确认，多个命中交 LLM，未命中则对学生说暂不支持并落本地待处理记录。归属确定后生成 D1、D2。

**判型单位是目标，不是整题。** 阶段①按目标输出特征，多问题的每个小问各有一组 `target_ref` 相同的特征。阶段②把这组特征当作一道独立的题来做全部检查、命中分流、知识点点亮和 D1/D2；同一题的不同小问可以属于不同题型，也可以一问支持、一问暂不支持。单问题只有 `/root/goals/0` 一个目标。D1 的片段定位只在该小问的题面段落及题干共用部分中进行。

```text
阶段①结果（candidate + features + statuses）
→ 输入准入检查；不合格则 input_error，停止本次判型
→ 程序按识别契约检查全部已登记题型
→ 恰好一个得到支持：程序确认主要归属
→ 两个及以上得到支持：LLM 在候选中选定主要归属；失败则该目标 selection_failed
→ 零个得到支持：不调用 LLM；学生端「暂不支持」；写入本地待处理记录
→ 归属已定时，程序生成 D1、D2
```

本阶段做：

- 三份识别契约：`type-quantified-quadratic`、`type-parameter-quadratic-solve`、`type-amgm-quantified`。
- 对每个题型的每个分支做三态检查，保留被排除的候选和依据。
- 唯一命中 / 多命中 / 未命中三条路径；多命中录制 LLM 选择；未命中落本地文件。
- 从 `original_text` 定位 D1 可点选片段；定位不到就不提供该选项。
- 用得到支持的题型和节点上的 `confuse` 生成 D2（仅归属已定时）。
- 以阶段①录制的 22 个真实候选（11 题，含 2 道多问题）作为测试输入，离线重放结构判定，不再请求视觉模型。

本阶段不做：选法、求解、方法前提检查、课程步骤、WebSocket、未命中记录的数据库表（与前端打通时再做）。知识点反向的“涉及”关系只给 D1 展示候选，不参与归属。题型规模只有三份契约，直接遍历，不做倒排索引。

## 2. 输入

正常输入是阶段①的 `stage-one-result.json`，先检查契约与完成状态，再读取题意和特征：

| 字段 | 用途 |
| --- | --- |
| `contract`、`run_id`、`statuses` | 校验版本、来源和阶段①完成状态；保存到阶段②输入检查记录 |
| `candidate.original_text` | D1 片段定位与展示 |
| `candidate.root` | 校验候选及目标引用；按需验证时读取量词关系。结构判型仍只使用已有特征，不重新提取题意或计算特征 |
| `features[]` | 判型唯一的结构证据。按 `target_ref` 分组，每组读取 `feature_id`、`status`、`value`。`calculation`、`diagnostics` 不参与匹配 |

阶段①失败时也会保留 `candidate/features` 供调试，不能以“文件存在”或“特征齐全”作为准入依据。本阶段读取已验收的阶段①产物，入口必须同时满足：

1. 通过 `graph-stage-one-result/v2` Schema，`candidate` 非空，并通过阶段①现有的候选校验；契约缺失或版本不支持时拒绝。
2. `statuses.extraction == "reviewed_candidate"`，且 `source_reviewed`、`features`、`evaluation`、`passed` 均严格为 `true`。字段缺失不能默认为成功；`human_review=pending` 不阻断本阶段。
3. `features` 的 `target_ref` 均能解析到当前候选的目标，`scope` 与目标所属作用域一致；每个目标有完整的阶段①特征条目，且同一 `(target_ref, feature_id)` 不重复。完整允许带原因的 `unknown` 或 `conditional`，不要求每项已知。

`known/conditional` 的值还须符合阶段①注册表对应的结构、类型和枚举；该校验不重算特征。`source_refs` 只能指向本作用域或祖先的事实／定义条目及当前目标，拒绝失效指针和跨小问出处。条件、诊断保留对象列表，未知特征的空值不按已知值格式强行解释。

任一检查失败，顶层输出 `status=input_error`、`goals=[]` 和可定位到字段的 `input_diagnostics`；不执行判型、按需验证或 LLM，不生成 D1/D2，也不写“题型未支持”记录。调试报告仍展示输入拒绝原因。当前 `evaluation/passed` 准入适用于本计划的验收与录制入口；将来接入没有金标的学生上传输入时，须另行定义生产准入契约，不能伪造验收成功。

`status` 不是 `known` 的特征，对应检查为未知，不能当成不成立。

测试输入分两路，都不再识图：

- 确定性测试：11 题 `notation.gold.json` 经现有 `extract_features` 得到特征，直接测试内部检查执行器；不伪造原图复核状态来绕过对外入口。
- 录制回放：`recorded/live-v2-20261017-02` 的 22 个真实候选。经阶段①现有回放器核验录制、复核状态并重新验收，以新生成的 `stage-one-result.json` 通过上述入口；历史结果保持原样。视觉模型调用次数为 0。

## 3. 识别契约

契约放在 `site/data/knowledge-next/recognition/`，一题型一份，题型 ID 与节点 ID 相同。不写进节点 JSON，避免学生页契约和判型规则混在一起。

每份契约：

| 字段 | 要求 |
| --- | --- |
| `type_id` | 已有题型节点 |
| `branches[]` | 分支 ID、必要条件、排除条件。任一分支通过即支持该题型 |
| `checks[]` | 只比较阶段①已有特征的 `status` 和 `value`，不写表达式模式 |
| `student_cue` | 指向该题型节点 `features` 里的一条已有线索，供 D2 展示 |

不设 `direct` / `alternative` 角色：凡得到支持的题型都计入命中集合；命中个数决定是否调用 LLM。

`type-quantified-quadratic` 对应图谱节点 **“含参一元二次不等式的恒成立与存在成立问题”**：在给定域内要求不等式对所有取值成立（`∀`，恒成立），或至少对一个取值成立（`∃`，存在成立／有解），求参数的范围、最小值或最大值。这里的变量角色由量词和目标确定；Q08、Q09 关于量词变量为一次、关于目标变量为二次，也属于该节点的“更换主元”分支。识别契约沿用这个节点 ID，分为：

| 分支 | 必要条件 |
| --- | --- |
| 量词变量的二次式 | `quantifier` 为 ∀ 或 ∃；`goal.kind` 为 `find_range`、`find_minimum`、`find_maximum` 之一，所求为单一标量；`relation.operator` 为 `<`、`<=`、`>`、`>=` 之一；`degree_in_bound` 为 `exact` 且次数为 2，或为 `upper_bound` 且上界恰为 2（含参二次项系数可能为 0） |
| 更换主元 | 同样的量词、目标和不等号要求；`degree_in_goal.degree` 为 2；`degree_in_bound.degree` ≤ 1；`range_var_is_principal` 为假 |

上界为 1 或 0 的含参式（如 `∀x∈ℝ: a·x+1≥0`）不是二次式；`=`、`!=` 关系（如 `∃x∈ℝ: x²=a`）是方程或不等于条件，不属于恒成立、有解的不等式题。两个分支都按冲突处理，测试各用这两个反例覆盖。

`type-parameter-quadratic-solve`：必要条件是目标为求解集且系数含参；排除条件是 `quantifier` 存在。Q01–Q09 的目标都是 `find_range` 且带量词，该题型冲突。

`type-amgm-quantified`：结构前提是量词存在且目标为求单一参数的范围、最小值或最大值。和积结构不是阶段①特征，由第 5 节的按需验证给出；验证不可用时这项为未知，不支持也不排除。二次结构不作为它的排除条件。

极值目标保持题面语义：候选用 `{"kind":"find_minimum","expression":"a"}`（最大值同理），程序特征用 `{"kind":"find_minimum","symbol":"a"}`，不得伪改成 `find_range`。例如题 13 的 `∀x∈(0,1/2]: x²+a·x+1≥0`、求 `a` 的最小值，应提取量词、半开区间和二次结构并命中恒成立题型。此阶段不判断所求最值是否存在或可达；这些属于后续求解。复合目标如 `min(a+b)` 仍不在当前单标量结构提取范围内。D1 与页面目标选项按实际目标显示“最小值／最大值”，包括“则实数 a 的最小值为……”这类没有“求”字的填空题。

节点 `features` 里“通常转化为最值”这类方法提示不写入契约。

九题的结构命中（验证前）：

| 题目 | 通过的分支 | 含参求解 | 基本不等式（验证前） |
| --- | --- | --- | --- |
| Q01–Q03、Q06 | 量词变量的二次式 | 冲突 | 未知（未验证）→ 仅恒成立唯一命中 |
| Q04、Q05、Q07 | 量词变量的二次式 | 冲突 | 未知 → 仅恒成立唯一命中 |
| Q08、Q09 | 更换主元 | 冲突 | 未知 → 仅恒成立唯一命中 |

两道多问题按小问判定：

| 小问 | 通过的分支 | 含参求解 | 结论 |
| --- | --- | --- | --- |
| Q10（1） | 量词变量的二次式（∀，ℝ） | 冲突 | 恒成立唯一命中 |
| Q10（2） | 量词变量的二次式（∃，[1,2]） | 冲突 | 恒成立唯一命中 |
| Q11（1） | 无：阶段①对不含量词的关系不计算结构特征，相关检查均为未知 | 未知 | 未命中，该小问暂不支持并落待处理记录 |
| Q11（2） | 量词变量的二次式（∀，[1,3]，首项系数含参） | 冲突 | 恒成立唯一命中 |

Q11（1）是有意保留的缺口：要支持它，需要在阶段①特征注册表中为不含量词的关系增加特征，并补上含参求解的识别契约；数据结构不变。

Q01 在第 5 节验证通过后，恒成立与基本不等式**同时得到支持**，进入多命中，须调用 LLM；预期 LLM 选定 `type-quantified-quadratic` 为主要归属。验证未通过时仍为唯一命中，不调用 LLM。

## 4. 判定

程序对每份契约的每个分支评估全部检查：

1. 读取的特征不是 `known`，该检查为未知。
2. 分支的必要条件全满足、排除条件全不成立，分支得到支持。
3. 必要条件冲突或排除条件成立，分支冲突。
4. 其余情况，分支未知。
5. 题型的任一分支得到支持，题型得到支持。全部分支冲突，题型冲突。否则题型未知。

主要归属按命中个数：

| 得到支持的题型数 | 程序行为 | LLM | 学生端 |
| --- | --- | --- | --- |
| 1 | 确认为主要归属；来源 `program` | 不调用 | 正常 D1、D2 |
| ≥ 2 | 把候选与检查报告交给 LLM；校验通过后来源为 `llm` | 必须在候选中选一，引用本目标检查 ID；不能翻案冲突项，不能引入候选外题型 | 校验通过后出 D1、D2；未选中的支持题型标为替代思路。调用或响应校验失败时显示本目标判型失败，可重试 |
| 0 | 未命中；来源 `unsupported` | 不调用 | 「当前暂不支持该题型」；不出 D2 |

多命中首版每目标发起一次语义选择调用，不在阶段②自动修复或重新抽样；provider 的有限网络重试与超时配置沿用共享实现，并在调用记录中区分语义调用数和网络尝试数。Q01 成功路径仍预期一次选择调用。响应必须满足选择契约，选中 ID 属于当前 `supported`，所引用检查 ID 属于同一目标的当前报告且支持该选择；截断、无效 JSON、候选外选择或无效依据均不得采用。

选择请求的结构化题意只包含当前目标及祖先，支持候选仍按当前目标筛选。`original_text` 优先按 D1 的作用域范围截取；无法可靠截取时（例如没有小问标签或标签重复），退回完整原文作为背景，不阻断选择。请求的 `original_text_fallback` 和调用记录的 `input_warnings` 保存 `selection.scope_text_fallback` 及“未能按小问截取”的说明，明确当前目标的数学条件以 `goal/visible_scopes/supported_types` 为准。D1 仍保守省略无法定位的片段，主要归属和 D2 可正常生成。成功截取的请求及单问题保持原有格式与录制兼容。

调用超时、provider 失败或响应不合法时，该目标为 `status=selection_failed`，`primary=null`、`primary_source=null`，保留 `supported`、完整检查报告、请求、原始响应（如有）和错误诊断，不生成学生 D1/D2，不落 `unsupported` 记录，也不回退到程序任选一个候选。其他目标继续处理；全题汇总部分成功状态见第 8 节。用户重试时创建新的选择尝试记录，保留此前失败材料。

**未命中记录（本阶段用本地文件）**

写入 `internal/solver-runs/graph-guided-stage-two/unsupported/<run-id>/`（gitignore 目录），每条至少含：题意摘要或 `candidate` 引用、特征表、全部检查结论、时间戳、运行 ID。不建数据库表；与前端打通时再迁库并做后台列表。

验证关闭时，九道单问和 Q10、Q11（2）预期全部唯一命中、0 次 LLM；Q11（1）为真实的未命中样例。Q01 验证打开后预期 1 次 LLM。多命中 LLM 路径另用构造样例测。未命中记录按小问写入，记录中带 `target_ref` 和小问编号。

## 5. 基本不等式的按需验证

只验证“这条量词关系能否经恒等变形，变成可用基本不等式求界的和积结构”。不生成方法轨迹，不求参数范围。验证能力以后与阶段③共用；本阶段只接 Q01 这一处。

Q01 的预期证据固定为：$-x^2+2x+3=3+x(2-x)$；在 $0<x<2$ 上 $x+(2-x)=2$，故 $x(2-x)\le 1$，等号在 $x=1$ 取得；在其余实数上该积不大于 0。从而全实数上的最大值为 4。验证器必须给出这些步骤的可检查记录。做不到时返回未知及原因；此时不因「未知」去调用 LLM（仍可能因唯一命中恒成立而不调用）。

固定的是量词变量一侧的有界结构，参数一侧从受控 AST 的规范关系中实际分离，不写死为 $a^2-3a$。例如改为 $a$、$2a+1$ 或其他受支持的参数多项式，仍可验证该和积结构；分离后若残留量词变量（包括参数与量词变量的混合项），返回未知。分离步骤展示实际参数表达式，并保存内部符号到原题变量的映射。所求变量声明为全实数区间成员关系（如 $a\in(-\infty,+\infty)$）与默认实数域同等处理；该规则不放宽其他附加条件。

验证通过后 Q01 变为双命中，**必须**走 LLM 选定主归属；验收时期望选定恒成立。

Q02–Q09 不要求找出和积结构。验证器对它们返回未知是允许的，不影响唯一命中。

现有求解器里的基本不等式代码服务的是另一批题目，不直接搬来搜二次式。Q01 这一处写明确的有界变形和前提检查，不做成通用不等式搜索。

## 6. 由特征值取知识点

D1 要回答“这句话对应哪条知识”，图谱要点亮知识再连到题型，所以阶段②同步给出每个目标的知识点。**知识点只由特征值推出，不由判定出的题型反推**：学生先在 D1 认知识、再在 D2 选题型，若用题型反推知识点，D1 就成了拿 D2 的答案倒推；题型节点的 `knowledge` 是这一类题的通用清单，其中如“最值”属于选法内容，提前点亮会泄露方法；未命中时题型不存在，知识点仍需展示并写进待处理记录。

阶段①特征上的 `knowledge_refs` 是按特征静态登记的“可能关联”，与取值无关（例如 `quantifier` 同时挂全称和存在）。阶段②改用一份按值取用的规则表 `site/data/knowledge-next/recognition/feature-knowledge.json`，每条规则有稳定的 `rule_id`，写明特征、取值条件、点亮的知识条目，以及 D1 允许挂接的片段类别（量词、定义域、关系式、目标）。首批规则：

| 特征与取值 | 点亮的知识条目 |
| --- | --- |
| `quantifier` 为 ∀ | `quantifiers#universal` |
| `quantifier` 为 ∃ | `quantifiers#existential` |
| `bound_vars`、`free_vars`、`goal` 均为 `known` | `quantifiers#roles` |
| `domain` 为 `known` | `quantifiers#domain` |
| `relation.operator` 为 `<`、`<=`、`>`、`>=` 之一，且 `degree_in_bound` 或 `degree_in_goal` 为 2，或含参且上界为 2 | `quadratic-inequality#definition` |
| `degree_in_bound` 为 2，或含参且上界为 2 | `quadratic-function-properties#definition` |

二次不等式定义必须同时满足关系符与次数两项：只看次数会把二次方程当成二次不等式，例如合法输入“∃x∈ℝ:x²=a，求 a”的次数特征为 2、`relation.operator` 为 `=`，不点亮二次不等式定义；`relation` 为 `unknown` 时同样不点亮。二次函数性质只看关于量词变量的次数，不看关系符：上例要用 x² 的值域，仍点亮二次函数性质。

规则只读 `status=known` 的特征；`unknown` 不点亮任何知识，也不报错。`degree_in_bound` 为 1 时不点亮二次相关条目（Q08、Q09 关于量词变量是一次式，关于目标变量才是二次，因此只点亮二次不等式定义）。一次函数区间最值、函数最值、判别式等属于选法与步骤的知识，不在 D1 规则中，留给阶段③。规则表的知识引用由测试检查存在于图谱。

点亮结果用于三处：

1. **D1 片段**：定位器保留该片段直接命中的 `matched_feature_ids`，按片段类别选择本目标中已通过条件的知识规则，保存 `knowledge_rule_ids` 后挂接知识条目。`source_refs` 只用于追溯题意依据，不能按相同引用反查并挂上全部特征的知识。具体绑定见第 7 节。
2. **知识到题型的连线**：主要归属确定后，取“本题点亮的知识”（按节点 ID）与该题型 `knowledge` 的交集，在图谱上画出知识 → 题型的高亮线，对应 Demo 中由知识连到题型的那一步。交集外、只在题型清单里的知识（如 Q01 的 `function-range-extrema`）D1、D2 不点亮，留到 D3。
3. **诊断**：交集为空或明显偏小时写入报告，提示契约或规则表可能有缺口；不改变判型结论。

九题的预期：Q01–Q04、Q06、Q07 点亮 `quantifiers#universal`、`#roles`、`#domain`、`quadratic-inequality#definition`、`quadratic-function-properties#definition`；Q05 将全称换为 `quantifiers#existential`；Q08、Q09 点亮 `quantifiers#universal`、`#roles`、`#domain`、`quadratic-inequality#definition`，不点亮二次函数性质。多问题按小问：Q10（1）、Q11（2）同 Q01 一组，Q10（2）同 Q05 一组；Q11（1）的结构特征均为未知，不点亮任何知识，未命中记录中知识点为空。

## 7. D1、D2

仅在主要归属已确定（程序或 LLM）时生成学生 D1/D2；未命中时跳过 D2，D1 定位结果可仍展示在调试报告，但不作为学生判型题。输入不合格或本目标 `selection_failed` 时不生成学生片段。

D1 在 `original_text` 上定位片段。阶段①只保证转录与题源在“版式、TeX 拼写、叙述标点”之外一致（见阶段①评估的 `normalized_transcription`），不保证公式带 `$`；真实批次中 Q06/sample-02 的转录就是 `“∀x<0，x^2+ax+2≥0”为真命题，…`。因此 D1 的公式定位不依赖 `$`：

- 小问标签须满足叙述边界；裸写的 `f(1)`、`f (1)` 不作为 `(1)` 标签，不能让函数调用破坏整题范围定位。半角标题保留严格数学上下文过滤；全角 `（1）` 可在同一行紧跟裸公式末尾的数字，有无空格均可，同时继续排除 `f（1）`、`f₁（1）` 等函数调用。真实重复标签仍视为歧义。原文片段不包含尾随叙述空白，保留公式本身的定界符及准确偏移。

- **先归一，再切分**：在该目标可见的原文范围内识别完整 TeX 命令，按阶段①已有的显示等价规则将 `\le`、`\ge`、`\forall`、`\mathbb{R}` 等转成 Unicode，处理显示包装及分组；同时保留归一字符到原文区间的映射。不能先按不含反斜杠的字符集拆分裸 TeX，也不能直接用删除空白、乘号和叙述标点后的整题验收比较串定位。未知命令不能拆成变量名继续匹配，只省略对应候选片段。
- 公式候选区间：保留 `$...$` 定界信息，在归一后的对应区间内识别公式；无定界符的部分按公式字符游程切分，即 ASCII 字母数字与 `()[]{}+-*/^=<>|∞ℝ∈≤≥∀∃_'` 及夹在两个公式字符之间的 `.,;:` 组成的最长连续段。公式内部空白允许跨越；汉字和叙述标点作为边界，不能因归一被删除而把不同句子的公式拼在一起。一个游程可能含多个片段（如 `∀x<0,x^2+ax+2≥0`），按顶层 `,`、`:` 再切一次。
- 匹配后用位置映射还原原文的 `start/end`（Unicode 码点、左闭右开）和 `text`，满足 `text == original_text[start:end]`。页面使用 UTF-16 下标时由展示层转换。带 `$` 的 TeX、裸 TeX 和 Unicode 写法应产生相同的语义匹配，但各自保留准确原文区间。
- 题面公式按教材写法书写，与标准题意不同：`ax`、`mx` 是隐式乘法，`y<0`、`f(x)≥0` 引用题面里的别名或函数定义，而标准题意里乘号已显式、别名已展开（Q08/Q09 不保留 `y=…`）。因此片段不送现有记法解析器，而是经下面的题面读法转成代数式，再与特征值比较：
  1. **符号上下文**：取该目标的 `free_vars` 与 `bound_vars` 作为已知单字母变量。字母串若本身不是已知名、别名或函数名，且每个字母都是已知变量，则拆成乘积（`ax`→`a·x`、`kx`→`k·x`）；否则保留为一个名字，交由后续步骤判定。数字后接字母或括号、`)` 后接字母数字或括号都补乘号。
  2. **题面别名与函数**：同一目标可见的题面片段中，形如 `y=表达式`（`y` 不是已知变量）的记为别名，形如 `f(x)=表达式` 的记为单参函数；按题面顺序登记，后出现的片段可引用先登记的。关系片段中的别名直接代入，函数调用按实参代入函数体。
  3. **比较**：关系片段按顶层唯一的比较符拆成左右两边，算出“左−右”，与 `relation` 特征的“lhs−rhs”比较；比较符相同时差为零、或比较符方向相反时差的相反数为零即命中（`expand` 后判零，不做近似数值判断）。以 `∀`、`∃` 开头的量词前缀片段不作关系比较，交给量词词表与 `domain` 匹配。
  4. 任一步无法处理（未知名字、多个比较符、函数未登记等）只让该片段不成为选项，不报错。
- 用阶段①录制 `live-v2-20261017-02` 的 22 个候选做过离线可行性检查：按上述读法，24 个目标的关系特征都在各自题面上定位到片段，包括 Q06 的 `x^2+ax+2≥0`（含无 `$` 的 sample-02）、Q08 的 `y<0`、Q09 的 `y>0`、Q10 两问的 `f(x)≥0` 与 `f(x)<0`、Q11（2）的 `f(x)<-m+5`。实现时把这 24 个定位结果写成金标测试。
- 量词和目标措辞用固定词表：任意、所有、恒成立、存在、有解、取值范围。
- **否定命题的原文映射**：支持带引号的单量词命题后明确写“为／是假命题”，以及 `¬`、`\neg`、`\lnot` 标记的单量词命题。先界定否定作用域，再验证原文与已知特征的变量、定义域（含开闭端点）一致，量词 `∀↔∃` 且单个关系严格取补集（`>↔≤`、`≥↔<`）；关系两边交换仍走精确代数比较。只有全部核对通过才生成片段，量词片段引用包含否定语境的完整原句，量词／关系片段携带 `reading_transform.kind=quantifier_negation`。原文否定范围内不再走普通肯定匹配，不能用孤立的“恒成立”覆盖已整理的存在语义。复合命题、嵌套量词、双重否定或无法证明的映射保守省略并记 `d1.negation_not_mapped`；不按题号、参数字母或题目常数分支。
- **填空式目标**：除“求……取值范围”外，支持“则实数／参数……的取值范围为……”及带答案空格的问法。仍匹配完整目标符号，不能把 `am`、`m_1`、`m²`、`m+m` 的后缀误认作 `m`，也不把“已知实数 m 的取值范围为 [0,1]”当成所求。
- 命中的片段带 `target_ref`、`fragment_kind`、`matched_feature_ids`、`knowledge_rule_ids`、知识条目和 `source_refs`。量词措辞直接命中 `quantifier`（明确变量时也可命中 `bound_vars`）；范围片段命中 `domain`；所求措辞命中 `goal`；关系式片段命中 `relation`，并可结合该关系已计算的 `degree_in_bound/degree_in_goal` 应用二次结构知识规则。变量角色规则只挂在明确量词变量或目标变量的片段上。所有匹配及规则条件只读取当前目标的已知特征。
- Q01 的量词、定义域、关系可能都引用同一条 `/root/facts/...`，但片段“对任意”只挂全称量词，“实数 x”在量词语境下可挂定义域及变量角色，纯公式 `-x^2+2x+3≤a^2-3a` 只挂关系和二次结构对应的知识，不因共用事实引用挂上全称量词或定义域。组合片段可挂多个知识，但每条都必须有直接匹配及规则依据；目标级知识集合和片段级知识集合分别保留。
- 对不上任何特征的叙述片段才可作为干扰项。Q01 的“实数”是有效信息，不做干扰项。
- 某个线索定位不到就省略该选项，阶段②仍算完成。

D2 的选项集合为 `supported ∪ (confuse(supported) ∩ conflicted)`，去重后保留来源：全部得到支持的题型，加上它们的 `confuse` 中本轮已明确判为冲突的易混题型。`unknown`、未登记契约或未评估的题型不进入学生选项，只保留在调试报告。错误候选的反馈结合节点上的 `confuse.text` 与本目标冲突检查；得到支持但不是主要归属的选项标明替代思路，不能写成数学错误。该过滤规则适用于所有题目，不为 Q01 单设例外。

主要题型与替代思路的支持依据只取该题型中已通过的分支，未通过分支里的局部支持检查不混入。错误候选保留各分支的冲突依据。

Q01 的 D2 与 [Demo 设计](graph-walk-demo-q01-design.md) 一致：主要题型为恒成立，含参求解为错误候选；基本不等式在验证并经 LLM 选定主归属后，作为未选中的支持题型标为替代思路。验证尚未通过时，基本不等式不进入选项，也不写成错误。

## 8. 输出

`graph-stage-two-result/v1` 顶层含运行 ID、阶段①结果引用、`input_validation`、`input_diagnostics`、`status`、`goals[]` 和全题 LLM 调用汇总。`goals[]` 按题面顺序，每项对应一个目标，带 `target_ref`、小问编号以及下列字段：

| 字段 | 内容 |
| --- | --- |
| `status` | `resolved`（归属已确认）/ `unsupported`（零支持）/ `selection_failed`（多命中选择失败） |
| `diagnostics` | 该目标的错误码、消息及对应检查或调用引用；成功时可为空 |
| `knowledge` | 点亮的知识条目，每条带触发它的特征与取值；与主要归属的交集及连线 |
| `types` | 每份契约的结论、通过或冲突的分支、逐项检查 |
| `primary` | 仅 `resolved` 时为已确认的题型 ID；其余为 `null` |
| `primary_source` | `resolved` 时为 `program` 或 `llm`；`unsupported` 时为 `unsupported`；`selection_failed` 时为 `null` |
| `supported` | 全部得到支持的题型 ID（含未选中的） |
| `d1` / `d2` | 学生片段，仅 `resolved` 时生成；其余为 `null`。未命中的 D1 定位结果另存调试材料 |
| `verification` | 按需验证的输入、步骤和结论；未运行则说明原因 |
| `llm` | 本目标调用状态、候选列表、语义调用数、网络尝试数、超时配置、耗时、请求和响应引用、选择依据及校验结果；失败也保留。唯一命中与未命中路径为 `null` |
| `unsupported_record` | 未命中时本地记录路径；否则省略 |

顶层状态按以下规则汇总：输入准入失败为 `input_error`，`goals=[]`；准入通过后，目标均为 `resolved/unsupported` 时为 `completed`，一部分目标 `selection_failed`、其余目标已完成时为 `partial`，全部目标 `selection_failed` 时为 `failed`。`completed` 表示判型流程完成，不代表每个目标都得到支持。未确认归属的目标不能进入阶段③；已确认目标可独立继续。

调试报告沿用阶段①的离线 HTML：题图、输入准入结果、全题及各目标状态、特征、点亮的知识及触发依据、每份契约的检查、命中路径、D1 高亮及匹配特征、D2 选项、未命中记录入口，以及失败调用与诊断。输入失败和选择失败都要能打开报告。不新增阶段①出处标注要求；片段位置和知识绑定金标属于阶段②测试。
