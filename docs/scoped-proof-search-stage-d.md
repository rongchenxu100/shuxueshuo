# 阶段 D：搜索调度

2026-09-28。实现范围为 [架构设计](scoped-proof-search-architecture.md) 的 D：内部可注册策略、分层调度、授权事实检索、候选配额、会话预算、诊断和缓存。正式 Method、M11 应用身份和教学迁移仍属于 E；默认生产搜索入口未切换。

## 结构与入口

| 模块 | 职责 |
| --- | --- |
| `math_kernel/proof_search.py` | 策略包注册、SearchPolicy、确定性候选队列、预算租约和统一轨迹；不包含题号或具体不等式规则 |
| `math_kernel/real_proof_strategies.py` | bounded-real 规则包的策略构造器、结构匹配、精确算术计量和节点检查；不调用旧 `_Search.core` |
| `math_kernel/proof_fact_index.py` | 对 Runtime 已授权视图建立索引，去重、过滤已证明常数、稳定排序及有限邻接扩展 |
| `math_kernel/proof_search_session.py` | 小上下文逐步扩大、跨行总预算、成功缓存及最小依赖上下文重建 |
| `runtime/scoped_proof_facts.py` | 内部 `overlay.prove_scheduled()` 入口、正常证书准入/事务发布、已验证快照缓存 |
| `tools/proof_search_stage_d.py` | 重建冻结请求、独立运行新搜索、保存完整请求/证明/轨迹和回放结果 |

底层入口为 `run_scheduled_request(context, request, ...) -> SearchRun`。Runtime 内部调用 `overlay.prove_scheduled(relation)`，无需指定 fact ID；读取仍由 C 的权限视图决定，成功后经过既有 `replay_record` 和提交前重建。`overlay.prove()` 保留旧行为，不构成新搜索失败后的自动回退。

策略包绑定准确的 `(package_id, ruleset_hash)`，声明每个策略需要的规则。注册时核对规则归属，禁用的策略或缺少允许规则的策略不进入匹配。构造节点时再次检查允许规则，最终通过独立 RuleRegistry 回放。新增测试规则包使用自己的 engine/checker，不修改原规则包 hash。

## 搜索顺序与回溯

能力按 S0 已有证明、S1 结构符号、S2 等价传递、S3 专门规则、S4 有限代数排序。排序键为 `(phase, cost, subgoal_count, dependency_count, strategy_id, candidate_key)`。匹配阶段只检查结构；需要精确代数的判断在候选执行阶段计费。

初版从旧搜索提取数学构造能力，分别命名注册；旧 `_Search` 在迁移期保留供旧入口使用。新路径继承 checker 环境，不继承或调用旧搜索。多项式恒等证明先尝试不使用等式前提的候选；一般等式归约留在 S4。根式/幂的定义域和操作数符号先于复杂代数改写。

递归子目标使用相同调度器，原始 AST 的定义域义务先证明。活动目标阻断当前循环，失败不缓存为数学上的“不可证明”。失败候选回滚节点区、节点编号、局部成功缓存和深度信息；算术工作不退款。最终只输出成功根可达的节点，并按旧证书格式重新编号。

## 预算与诊断

原有 ProofLimits 的默认、消元、换元及两种嵌套配置均保留；外部传入预算时使用其实际 limits，不重置为默认值。

`layered-search/v1` 的附加调度限额：

| 项目 | 上限 |
| --- | ---: |
| 单请求候选 | 512 |
| 单候选 attempts / reductions / nodes | 96 / 48 / 192 |
| 会话精确算术操作 / 单候选算术操作 | 65536 / 8192 |
| 单请求详细轨迹 | 256 条；另记丢弃条数 |
| 检索候选 / 去重后的授权事实总量 | 64 / 4096 |
| 成功缓存 / 快照校验缓存 | 各 64 项 |

精确算术操作包括有理式构造、加乘幂、多项式差式/除法/GCD/归约、线性组合、比例与常数区间计算；各运算内部仍保留原系数、项数、次数等结构上限。独立 checker 回放使用自己的有效 profile，不依赖搜索缓存。

候选租约包含递归子目标的全部费用。子目标耗尽祖先租约时，异常返回该租约所属候选，不能在过期租约下继续尝试子候选。局部超限为 `strategy_budget_exhausted`；真正耗尽会话总账为 `proof_search_exhausted`。候选产生的中间表达式超出结构能力时，该候选不可用；原始输入校验仍在调度前拒绝超限。

诊断记录 policy/hash、实际 limits、manifest/context hash、原目标位置、策略/阶段、子目标摘要、实际前提、预算增量和结果。日志截断不影响计数。策略的成功节点先检查再缓存；最终结果再次独立回放。

## 检索、去重与缓存

索引包含关系结构、关系类型、AST 子树、符号身份、完整子式的正性/非零、孤立变量等式、版本、producer 和依赖反向索引。精确匹配优先，随后为定义域、等式、子树及有限符号邻接关系；达到上限时记录截断原因。

按 `(statement_key, validity)` 去重，选择稳定的原始证据代表。已证明的纯常数不进入检索；**原始常数前提保留**，不能绕过 checker 的有限矛盾检测。去重发生在检索索引，原始提交记录和 fact ID 不重写：既有证书对重复来源的引用继续可回放。

局部上下文按 4、8、当前 profile 的前提上限扩大，不枚举任意前提组合，也不将整个事实库交给归约器。每轮从同一总账分配额度，为后续上下文保留资源。成功后移除未使用前提，在准确的新上下文中重新检查并重建证书；实际依赖进入 proof_reads。

成功缓存键包含请求、committed manifest、调用授权、符号绑定、Scope、完整事实视图指纹、policy 和 limits。取出时仍回放缓存证书。缓存不跨快照静默复用，不保存不完整搜索的失败。

快照校验缓存绑定完整 manifest/根事实内容、source context、全部调用授权、Scope 信息和事实类型注册表身份。Runtime fork 可以继承缓存，但授权或快照变化会失效；独立 restore 从空缓存重放全部生产证书。提交前仍重建候选增量；缓存不能替代事务校验。

新搜索提交的辅助记录携带 policy/hash、manifest 和 authority 元数据。旧记录不要求这些字段，回放不会调用搜索，也不要求当前 SearchPolicy 与生成时相同。

## 验收与边界

- D 专项 42 项：真实数学规则、错误关系/缺域拒绝、规则及包禁用、扩展包隔离、预算租约、失败回滚、五种有效 profile、无关事实扰动、去重/常数、等式链检索、缓存隔离、跨 Scope 拒绝、事务依赖及独立恢复。两个冻结局部推导（分别展开为 13、18 条关系）还完整运行于真实授权 overlay 的单一搜索会话中，沿用默认总预算，通过事务提交并在禁用搜索后恢复。
- 四个 A 阶段冻结样本产生 168 个已解析请求：**166 个关系/定义域/关系束请求在新搜索中成功并独立回放**。两个外层见证调度请求单列为 E 的 M13 入口迁移，不计为 D 成功；其内部已替换赋值的数学请求包含在 166 个请求内。
- 冻结比较重建的是原执行的准确局部上下文，不宣称正式 Runtime 已用新事实检索跑完五 Method 链。实际授权事实检索、跨调用 proof_reads 和恢复另由 D/C 集成测试验证。
- 冻结失败样本在 A 时已因早期修复通过旧内核，本阶段不宣称首次修好这些历史数学输入，也不把不同口径的 attempts 相比得出性能提升。

完整日志、压缩请求/证书/轨迹、初次失败记录和复现说明见 [验证目录](validation/scoped-proof-search-stage-d/README.md)。未调用真实 LLM，未进行浏览器检查或部署。

下一阶段 E 才切换正式 Method 会话，迁移 M01 原条件协议、M11 本次应用契约、M13 见证入口及教学证据。三个阶段 A 严格预期失败继续保留；不把 D 完成等同于 E/F 或 5C 最终验收完成。

## 审查修订

- 符号绑定在 C 的 `VerifiedMathFact.__post_init__` 已按关系 AST 裁剪；本轮索引和邻接扩展也直接读取 AST 中的符号，新增不相关变量不进入候选池的测试。q30 事实经共享变量连通后 `matched == available` 本身不代表绑定未裁剪。
- `prove_scheduled` 建索引前按调用授权的 validity 过滤本调用候选，避免带未授权定义引用的精确匹配遮蔽其他合法证法。
- 单请求候选队列和累计候选上限使用 `strategy_budget_exhausted`，携带请求所属租约，直接退出当前请求并允许会话扩大上下文；会话总账不退款。
- 快照缓存键改为注册表结构指纹（类型、事实种类、发布者、无条件标记、回调限定名）。额外保留注册表强引用；更换注册表时清空缓存，包括 fork 继承前的校验，以隔离限定名相同的不同闭包。
- 策略匹配改为按名字惰性分派；只有需要前提等式或相关关系的策略才扫描这些集合，不再每次求值全部适用性判断。
- 4096 条上限作用于去重和常数过滤后的有效索引；重复证据仍保留在原始事务中。测试覆盖 4100 条同关系记录在唯一事实上限为 1 时成功、第二种关系超限时拒绝。

新增 6 项审查回归。最终结果和本次存档见验证目录的 review 记录；未切换正式生产入口。

迁移至 F 前，旧 `_Search.core` 与策略包的数学构造并存。数学规则构造的修复必须检查两条路径，并保持冻结 shadow 比较工具可运行；不能只更新一份实现后依靠旧记录回放代替搜索兼容性验证。
