# 阶段 F1：性能基础

日期：2026-09-28。依据 [架构计划](scoped-proof-search-architecture.md) 第 14.6、15 节实施。F1 已完成；F2 产物去重、F3 全量验收与清理仍待实施。默认仍为 `bound-conditions/v1`，本次不调用真实 LLM、不改页面、不部署。

## 实现

### 不可变元数据

事实、有效性、取等要求及调用授权在构造时将序列输入递归复制为 tuple，拒绝可变叶子及未验证的值类型子类。提交、快照持有不可变事实与提交元组。缓存 `statement_key`、`fact_id`、调用指纹、`commit_id`、canonical bytes 和 manifest；`dataclasses.replace` 生成新对象及新缓存。

`to_payload()` 总是返回新字典，不把缓存的可变字典交给调用者。缓存属性不是 dataclass 字段，不进入 `asdict`、外部证据或原有 hash。manifest 流式读取各提交的 canonical bytes，生成与原 `digest((source_hash, commit_payloads))` 完全一致的字节序列；未更换 hash 算法、证书 schema 或规则包。

### 生产验证与消费授权分离

已验证前缀的缓存键包含完整 manifest、根事实、认证原条件及限制、绑定、已提交生产调用的授权与相对顺序、生产者对事实 Scope 的实际可见性、事实类型注册与 checker 规则版本。事实注册表或 checker 注册表对象替换时清空 memo，避免相同限定名的不同回调共享验证结果。

只存在于未来调用的授权，以及 Scope 中无关输出，不参与生产证书缓存键。构造函数、`register_call()`、`begin()` 及恢复单个提交时共用 `_validate_grant()`，显式检查 Scope 存在且与 validity 一致、符号名与身份不重复、依赖不指向未来或自身。`prepare_scoped_call` 通过 `register_call()` 追加授权；注册失败不改变调用列表。每次 `begin()` 在快照校验和事实视图构造之前校验当前授权，再检查执行顺序、已提交依赖，并按当前消费者的 Scope、符号身份和 validity 重新筛选事实。缓存命中不能授予当前调用读取权限。

memo 按执行实例保存，最多 64 项，可信分支可复制；没有全局验证缓存，也没有可由外部证据自报的“已验证”标记。不可变元数据缓存随值对象生命周期释放。

### 增量恢复

`restore()` 保留原接口。先逐项核对外部输出 hash，再比较传入证据与内存前缀的完整 canonical 内容。只有内容一致且当前授权下验证有效的前缀可以复用；随后在私有分支检查新增提交，最后核对完整产物并一次性替换快照。后段失败时原快照不变。

Retry 原来依次恢复长度 1、2、3、4、5 的前缀，现在同样五次调用只重放各自新增的一项，共 5 次；首次求解同样只需检查每个新提交，共 5 次。新实例没有验证 memo，必须从头检查所有提交。

当前 `restore()` 遇到比内存快照更短的检查点时仍从头回放该前缀，不复用内存校验；这是保守路径。v2 Retry 当前从新事实库逐段增长，已覆盖的增量恢复场景不受影响。未来若支持原事实库原地截短，应另补复用与撤销测试。

该变化消除的是重复数学重放，并不宣称整条链所有操作均为线性复杂度。既有完整前缀 manifest、外部证据比对和递归嵌入的 `previous_bound` 仍有成本；产物去重属于 F2，共享证据 DAG 仍是独立后续迁移。

## 性能与正确性

使用相同冻结 q30、显式 v2 和完整调试输出。优化前后各三次顺序运行，每次创建新的 Runtime；计时不含真实模型等待。具体中位数和范围以 [验证记录](validation/scoped-proof-search-stage-f1/README.md) 为准。三次普通冷回放是同进程的新事实库，另有三次独立进程冷回放，二者不混称。

| 场景 | 重放提交次数：优化前 → 优化后 |
|---|---:|
| 首轮完整求解 | 25 → 5 |
| Runtime Retry | 15 → 5 |
| 新事实库冷回放 | 5 → 5 |
| 热校验 | 0 → 0 |

优化前后三轮均得到最小值 4，5 个提交的完整快照 SHA-256 均为 `20cb39a69736494a2916b8ebb8f973fc9caa8f47fb51a09af80b8bd1d7b804ac`，序列化大小均为 3,848,202 字节。独立进程冷回放禁用旧、新搜索，仍检查全部 5 个提交。外部授权来自单独冻结的 Runtime 授权 fixture，未从待回放证书自建权限。

测试覆盖序列别名、返回字典污染、对象替换、不可变叶子、无关输出、生产/消费权限分离、符号身份、换元定义、状态版本、Scope 可见性、注册表变化、前缀篡改、错误输出绑定、事务原子性与冷回放。q30 真实链测试直接断言求解、冷回放和 Retry 各 5 次，不能通过删除 checker 来达到计数。

相关回归 257 项通过；最后补充拒绝未验证值类型子类后，F1 最终 18 项及 F1/D/C 核心 82 项通过。166 份冻结数学请求独立回放通过。此处没有把 F3 的完整 Solver 回归、默认切换或真实 Planner 验收标为完成。

## F1 授权边界审查修订

此前新授权的格式检查依赖缓存失效触发构造函数，F1 收窄 key 后会推迟到提交；现已改为显式注册和读取前校验。新增 13 项测试覆盖六类坏授权在注册及绕过注册后的 begin 入口拒绝，且禁止触发快照校验或提交重放；合法新授权仍保持生产证明缓存命中。审查修订验证与独立代码指纹见验证目录，原三轮性能数据保留为修订前测量，不冒充本次重新测量。
