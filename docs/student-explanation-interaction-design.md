# 学生讲解模式：交互设计（扩展设计）

本文保留“我来讲解”实验的交互目标与组件设计；未接入实验的组件和语音能力仍属设计范围。当前会话与候选行为以[会话上下文](student-explanation-context-design.md)为准。

## 1. 现在的问题

当前页面从上到下依次是：介绍、题目、思路切换、板书、当前式子、最近 4 条对话、输入框，以及默认折叠的数学操作表单。

| 问题 | 表现 |
| --- | --- |
| 表达只能靠打字 | 可点的对象只有固定的 2～4 个按钮；数学操作表单要写 `1/(2*m+1)` 这样的 ASCII 语法，而且默认折叠 |
| 注意力被拉散 | 学生要在底部输入，反馈出现在输入框上方的对话区，结果出现在更上方的板书，需要上下滚动 |
| 看不到系统怎么理解的 | 卡片只显示结果。模型从"那两个分式"推断出具体两项，学生看不出来，也没有地方纠正 |
| 反馈没有信息量 | 成功统一回复"已按你的思路验算，并整理到板书"；错误只有一行文字 |
| 追问只能用文字回答 | 系统问"1 怎么构造"，学生只能再打一段字 |
| 卡片不体现学生的思路 | "你的思路"只引用最后一句话，看不到理由，也看不到这一步是讲通了、还是系统补全的 |
| 操作入口分散 | 每张卡片都有"从这一步另开思路"按钮，顶部还有下拉框和两个按钮 |

## 2. 原则

1. **点选表达"对什么"，说或写表达"做什么、为什么"。** 数学对象尽量点出来，不让学生打公式；理由用自然语言，可以用系统语音输入法。
2. **系统的理解要可见、可纠正。** 先执行，再在结果上标出哪些参数是推断出来的，学生可以点开纠正。不在每轮执行前要求确认，避免打断。
3. **追问用小组件回答。** 问哪个对象，就在式子上高亮候选项；问缺什么参数，就在句子里留一个空。
4. **注意力集中在一处。** 当前式子、正在进行的讨论和输入框放在同一块区域。
5. **区分学生的贡献和系统的贡献。** 卡片上明确显示讲解状态，以及哪些内容由系统代算。
6. **只用页面、只用对话，都能独立解出这道题；两者结合时比任何一种单独使用都更方便。** 这是整体设计的验收标准，见第 8 节。

## 3. 页面结构

```text
┌──────────────────────────────────────────┐
│ 目标：求 F 的最小值   已有下界 1/2 · 取等待验证 │  ← 目标条，固定在顶部
├──────────────────────────────────────────┤
│ ① 整理条件         讲通                     │
│   "两个分母加起来是 8"                      │  ← 已完成的步骤卡，默认收起
│ ② 乘 1 配式        讲通（有提示）  ▸ 对话 3 │
│ ③ 基本不等式       待说明                   │
│   还需说明：为什么这两项可以用基本不等式？    │
├──────────────────────────────────────────┤
│ 现在的式子                                  │  ← 前沿讲解区
│   F = 1/4 + [(n+1)/(8(2m+1))] + [(2m+1)/(8(n+1))] │    式子中的项可以直接点
│   条件：2m+n=6，m>0，n>0                     │
│ ┄┄ 正在讨论 ┄┄                              │
│   你：m=n 时取等                             │
│   系统：回代得 m=n=2，F=8/15，没有达到 1/2   │  ← 草稿卡：不成立的尝试
│ ┌──────────────────────────────────────┐ │
│ │ 已选：(n+1)/(8(2m+1))  ×               │ │
│ │ [我想…▾]  说说你的思路……        [讲完了] │ │  ← 输入
│ └──────────────────────────────────────┘ │
└──────────────────────────────────────────┘
```

页面分三块：

- **目标条**：题目目标和当前进展（未开始、已有下界、已证明最小值），固定在顶部。题目原文可以点开查看。
- **板书**：已生成的步骤卡，按顺序排列，默认收起，只显示标题、状态和学生原话。
- **前沿讲解区**：当前式子、正在进行的讨论、输入框，放在页面底部，是学生的注意力所在。新的步骤生成后，从这里"落"到上方的板书。

手机上保持单列，前沿讲解区占据屏幕下半部分，板书可以向上滚动回看。

## 4. 组件

### 4.1 可点的当前式子

当前式子中的每一项、每个分母，以及条件里的式子都可以直接点选，不再放在下面的一排按钮里。实现上用 KaTeX 的 `\htmlData` 给子式打上对象标识，标识来自执行器给出的可引用对象。

- 点选后，输入区显示"已选"标签，可以删除。最多选两个。
- 已有步骤的结果也可以引用，例如点第 1 步卡片上的 \((2m+1)+(n+1)=8\)，表示"用这个结论"。
- 提交时把选中对象的标识一起发送，服务端按提交时的对象解析指代。

### 4.2 "我想…"方法入口与句子模板

输入框左侧的"我想…"展开后列出可用的操作：整理一个关系、换元、给式子乘一个因子、展开化简、用基本不等式、检查取等，以及"我有别的想法"。选中后，输入区变成一个句子模板：

| 操作 | 模板 |
| --- | --- |
| 换元 | 设 [　] = [　] |
| 乘因子 | 给 [整个式子 ▾] 乘 [　]，因为 [　] |
| 基本不等式 | 对 [　] 和 [　] 用基本不等式，因为 [　] |
| 检查取等 | 当 [　] = [　] 时取等 |

- 空格可以点式子填入，也可以输入；输入时提供一个简单的数学键盘（分数、括号、常用变量），不要求写 `*` 和 `/`。
- "因为"后面是自由文字，这是学生讲理由的位置，作为关键判断的来源。
- 模板提交时不调用模型，直接交给执行器；"因为"部分如果填写了，再调用模型提取判断。

这替代了现在折叠起来的数学操作表单。自由讲解仍然是默认方式，"我想…"只是辅助。

### 4.3 理解回显

步骤生成后，卡片上用一句话显示系统实际执行了什么，例如：

> 我理解为：对 \(\frac{n+1}{8(2m+1)}\) 和 \(\frac{2m+1}{8(n+1)}\) 用基本不等式。

由模型推断出来的参数（不是学生说的或点的）用虚线框标出。点击虚线框会打开"不是这个意思"：在步骤上开一个讨论，把这个操作以模板形式预填，学生改完重新提交。

### 4.4 追问组件

系统追问时，问题直接以可操作的形式出现在前沿讲解区：

| 追问类型 | 呈现 |
| --- | --- |
| 指代不唯一 | 在式子上高亮所有候选项，提示"你说的是哪两项？点一下" |
| 缺少参数 | 显示对应模板，已知的部分预填好，只留缺的空，例如"给整个式子乘 [　]" |
| 缺少关键判断 | 先问开放式问题，例如"为什么这两项可以用基本不等式？"，学生用文字回答；只用页面时不追问（见 8.3 节） |

缺少关键判断时，追问按梯度逐级收窄：

1. 开放式提问；
2. 学生答不出或答偏后，缩小范围，例如"这两项的积有什么特点？"；
3. 再给选项，例如"积是定值 / 和是定值 / 都不是"；
4. 最后由系统讲解。

每一级都记入判断来源。到第 3、4 级时，该判断记为"提示后"或"系统讲解"。学生随时可以点"先跳过"，步骤保持"待说明"，继续往下讲。

### 4.5 草稿卡：不成立的尝试

数学不成立或暂不支持的操作，在前沿讲解区显示为虚线边框、没有编号的草稿卡，不进入板书。草稿卡展示具体是哪个检查没通过，而不只是一句话：

> 当 \(m=n\) 时：由 \(2m+n=6\) 得 \(m=n=2\)，此时两个分母为 \(5\) 和 \(3\)，\(F=\frac8{15}\)，没有达到下界 \(\frac12\)。

草稿卡下方有两个操作："改一下"把这次尝试以模板形式预填；"换个想法"放弃这次尝试，清空输入。

### 4.6 预测再揭示

对于教学上希望学生自己预判的结果，系统算出后先不显示，在卡片上留一个输入框："你觉得结果是？"。学生填写后再揭示正确结果，并记录预测是否正确；也可以点"直接看"。

哪些结果需要预测，由关键判断策略决定，例如在判断策略中把"下界的值"标为 `predict`。默认不开启，避免每一步都被打断。

### 4.7 步骤卡

| 区域 | 内容 |
| --- | --- |
| 标题行 | 编号、标题、讲解状态：讲通 / 讲通（有提示） / 待说明 |
| 你的思路 | 学生在这次讨论中说的原话和理由，按时间合并；"对话 N"可以展开完整对话 |
| 结果 | 核验后的公式，或对应的专用组件 |
| 系统代算 | 默认折叠，列出系统完成的计算 |
| 还需说明 | 只在"待说明"时出现，显示当前唯一的追问 |
| 更多 | 菜单中放"追问这一步""从这里换个思路"，不再每张卡片放一个按钮 |

### 4.8 思路切换与完成报告

- 思路切换改成目标条下方的标签页："思路 1 / 思路 2"。只有一条思路时不显示。
- 证明出最小值后，显示一份讲解报告：每一步由谁提出、讲解状态、哪些判断是提示后说出或由系统补全的。这份报告也是之后学习记录的依据。

## 5. 用新交互走一遍 Q12

1. 学生在式子上点 \(2m+1\) 和 \(n+1\)，说"这两个加起来是 8，所以可以乘一个 1"。
2. 第 1 步"整理关系"落入板书，状态为讲通。前沿讲解区出现追问模板："给 [整个式子 ▾] 乘 [　]"。
3. 学生点第 1 步卡片上的结论，再输入"÷8"，空格填为 \(\frac{(2m+1)+(n+1)}8\)，提交。第 2 步"乘 1 配式"落入板书，挂着前两轮对话。
4. 学生说"那两个分式用基本不等式"。当前式子中只有两个比值项，指代唯一，生成第 3 步。卡片显示"我理解为：对……用基本不等式"，两项用虚线框标出，因为它们是推断出来的；状态为待说明，追问"为什么这两项可以用基本不等式？"。
5. 学生回答"它们乘起来是定值"，第 3 步变为讲通，目标条显示"已有下界 1/2 · 取等待验证"。
6. 学生说"m=n 时取等"，前沿讲解区出现草稿卡，展示 \(m=n=2\) 时 \(F=\frac8{15}\)。学生点"改一下"，把关系改成"两个分式相等"，生成第 4 步，显示讲解报告。

## 6. 现有组件能否复用

`site/assets/practice/components.js` 中的换元、配式、基本不等式、取等组件，是为固定路线写的：选项、看板 HTML 和预期答案都由教师配置给定。用于讲解模式时需要调整：

- 完成态（如 `completedAmgm`）可以直接复用，参数改为来自核验结果；
- 补齐用的模板需要从当前式子的可引用对象生成选项，不能依赖教师配置中写好的选项和看板。

## 7. 分阶段

| 阶段 | 内容 | 理由 |
| --- | --- | --- |
| 第一阶段 | 页面结构改为目标条、板书、前沿讲解区；可点的当前式子；新的步骤卡（状态、学生原话、对话展开）；草稿卡；追问中的候选高亮与缺参模板 | 与会话上下文的内存实现同步完成，改动集中在展示层，效果提升最明显 |
| 第二阶段 | "我想…"与句子模板、数学键盘；理解回显中的纠正；追问梯度；讲解报告 | 需要模板生成和判断提取都稳定之后再做 |
| 第三阶段 | 预测再揭示；内置语音 | 需要先观察学生实际使用后再决定范围 |

第 8 节的三种交互方式会改变第二阶段的范围：理由控件、动作菜单、用点选拼式子（只用页面），以及对象编号、语音流程控制（只用对话），都应纳入第二阶段，并以 8.1 节的验收脚本作为完成标准。

## 8. 三种交互方式

### 8.1 验收标准

| 方式 | 要求 |
| --- | --- |
| 只用页面 | 不输入任何汉字（数学式子可以用点选和数学键盘拼出），从原式走到"证明出最小值"，每一步都达到"讲通"或"讲通（有提示）" |
| 只用对话 | 不点式子、不用表单和按钮（发送除外），只靠文字或语音完成同样的过程，包括指代对象和撤回、换思路等流程控制 |
| 页面加对话 | 完成同一件事所需的轮数和输入量，少于两种单独方式中较少的那一种 |

验收方法：Q12 的两条参考路线（直接配凑、换元）各写三套端到端脚本，分别只用页面、只用对话、页面加对话，三套都必须走到讲解报告。

### 8.2 统一的动作

三种方式产生同一套动作，执行器和会话上下文不区分动作从哪里来，只记录证据来源。

| 动作 | 页面来源 | 对话来源 |
| --- | --- | --- |
| 操作（7 种） | 选中对象后的动作菜单、句子模板 | 模型翻译学生的话 |
| 指代对象 | 在式子上点选 | 说编号（"第二项"）或说出式子 |
| 理由（关键判断） | 不追问 | 可以顺带说，讲错才指出 |
| 回答追问 | 点高亮的候选项、填缺参模板 | 直接回答 |
| 流程控制：撤回、换思路、回到第几步、先跳过、提示 | 按钮 | 说出来（"撤回上一步""回到第二步"） |

证据来源分为：说出、提示后。

规则：系统提出的指代、缺参问题，都必须既能点选回答，也能用话回答；页面上的每个动作，都可以附带一句话讲理由。

### 8.3 只用页面：需要补的部分

1. **不追问理由。** 系统只验算操作：成立的进入板书，不成立的给出原因，不要求学生用填空或选项补"为什么"。这一点后来推广到所有方式（见文首决定）。

   早先设计过填空、选项形式的理由控件，体验后认为是多余的负担，已删除。

2. **动作菜单。** 选中对象后弹出当前可用的操作，按执行器的能力过滤：选中两项时，可以用基本不等式或核对等式；选中一个分母时，可以设为新变量；什么都没选时，可以展开、合并或乘一个因子。从菜单发起的操作，来源记为"从菜单选择"（见 9.1）。

   纯页面页面的实现：页面列出"下一步可以这样做"的候选操作，学生点一下就执行。候选由程序根据当前式子和已经核对过的事实枚举，不调用模型：
   - 两个分母还没有设新变量时，给出"设 x = 2m+1""设 y = n+1"；
   - 两个分母之和还没有核对时，给出"(2m+1)+(n+1) = ？"，结果由学生自己填；
   - 核对出"某式 = 常数"之后，才给出"给整个式子乘 某式/常数"，所以关键构造不会先于它的依据出现；
   - 当前式子的每两项，给出"对这两项用基本不等式"（已经用过的不再给）；
   - 合并、展开只在会改变板书时给出；
   - 有了下界之后，才给出取等的候选。

   在式子里选中的项，相关的候选会排在前面。全部 7 个操作收进"自己写一步"，作为模板的兜底。报告里，从候选执行的步骤标"从候选中选择"；用模板写的步骤不额外标注。

3. **用点选拼式子。** 模板中的空格可以填入点选的对象、已有步骤的结论和数学键盘的输入，例如乘因子时拼出 \(\frac{①+②}{8}\)，不需要手写 `*` 和 `/`。

4. **提示。** 沿用现在的做法，由模型生成。"给点提示"按钮本身属于页面交互。

### 8.4 只用对话：需要补的部分

1. **对象编号。** 当前式子中的可引用对象显示编号 ①②③…；指代追问用文字列出带编号的候选项，学生可以说"第二项和第四项"。编号随当前式子一起传给模型。
2. **语音流程控制。** 模型可以输出流程控制动作：撤回、从第几步换思路、切换思路、放弃当前尝试、先跳过、讨论第几步、要提示。程序按对应按钮的逻辑执行，回复中说明执行结果。撤回之后可以再撤回。
3. **结果用话说清。** 每轮回复用一句话说明发生了什么，不依赖学生去看卡片（现有回复基本满足）。

### 8.5 页面加对话：比单独使用更方便的场景

| 场景 | 只用页面 | 只用对话 | 页面加对话 |
| --- | --- | --- | --- |
| 对两项用基本不等式并讲理由 | 点候选即可，但讲不了理由 | 说"那两个分式用基本不等式"，可能被追问指的是哪两项 | 点两项，说"用基本不等式，因为积是定值"，一轮完成 |
| 乘一个构造的 1 | 打开模板，用点选和键盘拼出因子 | 要说清完整的式子 | 说"乘一个 1"，系统给出缺参模板，点第 1 步的结论拼出因子 |
| 系统追问指代 | 点候选项 | 说编号 | 两种都可以，用最顺手的 |
| 页面上做完一步 | 只验算，不记录理由 | — | 直接用语音补理由 |
