# 交互题目：静态课程与一对一老师的职责

状态：**职责已确认，Q01–Q30 已实现静态练习与按需对话同步；本轮 Q10–Q30 未部署**。更新日期：2026-09-30。

适用范围：基本不等式章节，以 Q01 为样本。保持首版简单，不引入新的前端框架或通用教学脚本语言。

## 1. 核心约定

**HTML 是学生看到的课程，JSON 是老师理解和判断这节课所需的教学说明。**

- 每题有独立静态网页，可以承担题干、题意整理、步骤、公式推导、图形、答案和组件配置。
- 公共 JS/CSS 实现组件与流程。没有对话时，页面独立完成点选、填写、校验、反馈和步骤推进，不依赖后台。
- 每题后台 JSON 提供原题、可行路径、节点要求、通过标准、参考结论及引导依据；它不需要描述整个页面布局或复制全部展示模板。
- 学生请求对话或主动提示时，后台加载 JSON + Context + 通用 Prompt，成为了解当前题目和学生进度的一对一老师。
- 页面操作先记录在浏览器 Context 中，不必显示成聊天消息，也不必逐次调用 API。
- 不使用对话的练习不会创建后台教学会话。登录与个人学习标记已接入：完成一条完整路径后仅保存“练习过”和单字段自评状态，可跨设备读取标记，不保存或恢复步骤、答案、解法与练习历史。公共 `assets/learning` 组件独立处理完成保存、自评和题库展示，学习记录接口失败不影响本地练习。

## 3. 教师 JSON 与每一步的要求

**JSON 描述这道题如何教、每一步需要学生回答什么。** 其中的组件声明帮助老师将学生的文字答案对应到页面输入，不承担整页渲染职责。

| 内容 | 当前字段 | 边界 |
| --- | --- | --- |
| 原题、条件与目标 | `problem` | 老师理解本题的依据；网页可以独立展示同一题目 |
| 路径与问题 | `methods`、`routes`、`title`、`question` | 只列可完整练习的路径，用问题驱动学生思考 |
| 关键输入及通过标准 | `required_evidence`、`criteria` | 说明需要什么信息、哪些等价表达可以接受、哪些信息仍不足 |
| 数学答案与组件对应 | `expected_answer`、`interaction` | 提供组件候选项与答案，不能保存自动点击脚本 |
| 反馈 | `feedback`、`completion_reply` | 信息不足才引导，满足本步要求后不强行追加问题 |
| 教学参考结论 | `results` | 为后续讨论提供依据，不充当学生已经表达的证据 |

```json
{
  "question": "定和求积还是定积求和？",
  "interaction": {"type": "structure", "terms": ["m", "n"]},
  "expected_answer": {"terms": ["m", "n"], "fixed": "sum", "target": "product"}
}
```

点选与对话是同一次练习的两种表达方式。LLM 理解自然语言，后台按节点标准校验，页面使用相同组件显示结果。组件规则在公共代码中实现，JSON 不再保存 `text_autofill`、任意字段路径、动作脚本或联动操作序列。

实际填写、对话、已完成步骤和历次尝试属于 Context，不写回教师 JSON。组件提供的公式骨架、学生主动表达的信息和系统补充的推导应区分：在完整公式中填变量，不等于独立写出了该公式。

教师 JSON 中的 `problem.statement` 使用一条文本，公式可用 `$...$` / `$$...$$` 的 LaTeX；网页可以使用 HTML 数学标记或公共 KaTeX。公式排版字符串不作为组件校验协议。完整 Schema 尚未定稿，不增加重复的输入定义或通用规则语言。

- 开区间端点（Q05）：`quadraticGraph` 与 `reciprocalSumGraph` 的 `points` 新增可选 `open:true`，标记点画成空心，表示取不到；`axisExplorer` 新增 `open:true`，区间两端都画空心，较高一端改标“上端”。Q05“当 $1<x<2$ 时有解”用它们表示取值范围的上端取不到。

- 二次项系数含参、对称轴固定（Q07，$mx^2-mx-1$ 在 $[2,3]$ 上）：区间最值法按系数的符号分三种情况，`i_extremum` 用 `.graph-cases` 三张真实实例图（`coefficient:0` 画出退化的直线）代替 `axisExplorer`，不新增组件。`.case-merge-group` 内有三格时排成一行三栏；窄屏下情况名过长时，名称里的“（条件）”放进 `<span class="nowrap" data-math-text>`，外层名称不加 `data-math-text`（渲染按 `textContent` 重写，嵌套标签会丢失），使换行落在条件之前。
- 新增只读展示组件 `linearGraph`（挂载点 `data-linear-graph`，`runtime.js` 与其他图像一同渲染）：画 $y=\text{slope}\cdot t+\text{intercept}$，用于更换主元后关于主元的一次函数（Q08 的 $f(m)=(x^2-x+1)m-6$ 取 $x=0,2$ 的实例与边界处 $f(m)=2m-6$）。`bounds`、`interval`（区间外淡化）、`xTicks`、`points`（含 `place`）、`markSign`／`strict`、`variable` 与 `quadraticGraph` 用法相同；斜率为 $0$ 时画水平线，整段落在横轴上（$f\equiv0$）且 `strict` 时整段标红（Q09 边界 $x=1$）。Q09 用三张 `linearGraph` 放进 `.graph-cases`，对照斜率为正、零、负时最低点的位置。

### 4.1 路径入口

题目入口只展示本题可完整练习的可行路径，不固定列出全章所有方法，也不为凑选项加入不适合的方法。Q01 已只保留“直接应用基本不等式”和“消参法”两条路径（题目数据版本 4），并移除原来的其他方法专用说明配置。

可执行路径与节点内的选项分开定义。需要辨析错误时，在具体节点围绕明确的数学判断设计选项；学生主动提出其他方法时，通过对话理解其实际思路，不凭方法名称判错。

### 4.2 步骤内计算板（按后续题目需要实现）

**Q01 暂不需要计算板，本次只记录设计。** 后续讨论具体题目时，若某一步确实需要学生提出化简、代入、展开或配方请求，再为该节点增加此能力，不要求每题、每步都配置计算板。

首版计算板限制在当前步骤所需的计算，不扩展成整题自由求解工作区。学生用自然语言提出计算要求，LLM 结合原题条件和当前节点理解表达，返回结构化推导与结果；只计算到所请求的位置，不自动解完后续步骤。

计算板采用弹层，内容分为两个区域：

| 区域 | 内容约定 |
| --- | --- |
| 计算区 | 只展示数学语言：表达式、等式变形、不等式、变量范围和必要条件；推导行使用 LaTeX，不混入自然语言解释 |
| 反馈区 | 独立置于计算区下方，以自然语言说明错误、缺失条件或澄清问题；计算成功时可以不显示 |

计算失败需要区分原因，不把所有失败记为学生作答错误：

| 情况 | 计算区处理 | 反馈区处理 |
| --- | --- | --- |
| 计算成功 | 展示完整计算链及结果 | 可不显示 |
| 表达不明确 | 展示已识别的表达式；无法识别则留空 | 提出具体的澄清问题 |
| 数学操作不成立 | 保留成立的推导；出错行单独标记，不接入正确计算链 | 指出哪一步不成立及原因 |
| 条件不足 | 展示能够成立的部分，不补造条件 | 说明继续计算所缺的条件 |
| 模型或计算服务失败 | 保留已有内容，不编造结果 | 说明本次未完成，并支持重试 |

只有确认数学操作不成立时才指出学生的数学错误；表达不清、条件不足和服务故障均不能直接判为作答错误。

计算板使用公共展示组件和通用 Prompt。数学推导行与自然语言反馈作为不同数据字段返回，具体字段名和完整 Schema 在首道需要计算板的题目中确定。动态计算记录属于当前路径尝试、当前节点的 Context，不写回 Lesson JSON；关闭弹层不丢失记录，后续对话可以继续引用。

打开或关闭计算板不推进主流程。计算板是与学生讨论数学思路的工作区，其结果可以回到当前步骤：程序验证正确且满足本节点全部要求时，完成当前步骤；只解决部分要求时，将结果写入当前步骤并继续讨论；尚未通过验证时保留探索记录和反馈，不写成已确认事实。不能仅因模型输出了最终答案就完成整题。计算工具与校验范围待首个实际场景确定。

### 4.3 未来：数学探索工作区与逐步形成解题步骤

本节是后续综合题的方向，不纳入 Q01 或首版计算板的实现范围。“计算板”长期承担数学思路讨论，不局限于代数计算，按问题需要支持三种展示：

- 纯数学推导与结果。
- 图形与推导过程联动。
- 单图形探索，例如尝试添加辅助线、观察关系或修改构造。

推导区域仍只展示数学语言；错误、缺失条件和澄清问题由独立自然语言反馈区或对话承接。图形上支持必要的数学标记，但不能把视觉上看似成立的关系直接认定为已证明事实。

探索循环中的职责是：

| 参与方 | 职责 |
| --- | --- |
| 学生 | 提出下一步思路、选择方法或构造，并根据反馈调整尝试 |
| LLM | 理解学生表达，将其转成结构化计算、构造或验证请求；澄清歧义并解释反馈，不擅自替换成另一条解题路线 |
| 程序工具 | 执行受支持的计算、图形构造和数学验证，返回结果、失败位置或所缺条件 |
| 页面与 Context | 展示图形和推导，保存尝试及反馈，把通过验证的结果写入对应步骤 |

```text
学生提出思路 → LLM 理解并形成操作 → 程序计算／构造／验证
     ↑                                      ↓
修正或继续探索 ← 反馈与图形／推导展示 ← 结果或失败原因
                                            ↓
                         验证通过且匹配当前步骤要求
                                            ↓
                           写入步骤结果／通过当前步骤
```

**学生承担现有 Plan LLM 的核心规划职责：提出下一步做什么、使用什么方法、构造什么对象。** LLM 保留表达转译、澄清和教学引导职责，程序承担执行与验证，数学决策尽量留给学生。

| 现有求解系统 | 学生探索系统 |
| --- | --- |
| Plan LLM 提出数学计划 | 学生提出数学思路 |
| 生成可执行的结构化计划 | LLM 将学生表达转译为受支持的结构化操作 |
| Runtime 执行与验证 | 程序执行计算、构造并验证结果 |
| 失败反馈给 Plan LLM，由模型重试 | 将可理解的数学反馈交给学生，由学生调整后再次尝试 |

例如学生只说“试试作辅助线”，LLM 应帮助他明确如何构造、希望得到什么关系，不能未经表达或确认就替他补出整条解题计划。必要时可以给提示，但应区分学生提出的思路与系统提供的建议，不把系统补出的内容记为学生已经掌握或独立完成。

复用方向是现有 Runtime 的计算、验证和 retry 反馈能力，而不是把自主规划过程继续交给 Plan LLM。具体接入需按题目与操作能力验证，当前尚未完成这层复用。反馈应指出可理解的数学问题；工具暂不支持或执行失败，不能伪装成学生思路错误。

未来综合题的步骤可以通过师生讨论逐步形成，不要求一开始枚举完整路径。拟议步骤、探索中的计算或构造、已验证结论需要分别记录；新步骤以原题条件和已有可信结论为依据，不能通过修改步骤要求来迁就错误答案。预设路径继续作为教学参考，具体的动态步骤协议与 Schema 留到综合题场景再确定。

## 5. 静态练习与按需对话

### 5.1 静态练习

```text
每题 HTML（内容、模板、组件配置和本地答案）
                  ↓
公共 JS → 点选／填写／本地校验 → 浏览器 Context → 下一步或反馈
```

页面打开、点选、提交、切换已提供的路径、重新练习均不调用 API。打开候选菜单、滚动等不计入学习事件；有意义的选择、填写、提交和路径切换保存为有唯一 ID 的结构化操作。10 秒无操作仅显示呼吸邀请，不自动调用 LLM。

### 5.2 发起对话

```text
未同步的页面操作 + 本次文字／主动提示 + 题目版本
                         ↓
         后台校验版本、按顺序重放操作并更新临时 Context
                         ↓
          教师 JSON + 最新 Context + 通用 Prompt → LLM
                         ↓
           校验模型建议 → 提交本轮 Context → 回复与状态
                         ↓
                页面更新同一组组件
```

首次对话才创建后台会话，随后发送本轮请求；后续对话只携带尚未确认同步的页面操作。调用期间暂时锁定作答，重新练习仍可用。原有单 UI 事件 API 保留兼容，但新页面不使用逐次请求。

后台不接受浏览器声称的“已完成”，只根据教师 JSON 重新校验操作。每批携带 `lesson_version`、服务端 `revision`、本轮 `event_id`；各操作有自己的 ID 及所属路径、步骤、尝试序号。重放和模型处理在临时 Context 中执行，成功后整体提交，模型失败不保存半轮记录。相同请求 ID 重试返回缓存结果，避免重复调用和重复推进。

### 5.3 失败、重试与重新练习

- API 不可用或模型失败时，保留输入和本地进度，学生仍能继续点选；对话显示可重试提示。
- 重试使用原请求和原事件 ID；成功后再将失败期间新增的本地操作合并到返回状态，这些新增操作在下次对话同步。
- 若老师已确认了学生在失败期间也完成的同一步，不将旧步骤的填写重新应用到下一步。
- 若迟到的回复切换路径，与后续本地操作冲突，保留本地进度并明确提示；本版不自动解决分叉，需要重新练习开启新对话。
- “重新练习”清空当前浏览器 Context，下一次对话才创建新后台会话；旧请求结果不能覆盖新练习。
- 当前刷新会从头开始，浏览器 Context 不持久化。服务端会话仍在单进程内存中，重启或过期后可继续本地点选，但恢复对话需要重新练习；跨设备保存未实现。

## 6. Context 与教学定义

| 固定教学定义 | 每次练习的 Context |
| --- | --- |
| HTML 中的课程和组件配置 | 实际选择与填写、当前路径与步骤 |
| 教师 JSON 中的路径与通过标准 | 有意义的页面操作、已完成节点、待同步操作 |
| 参考推导、提示和完成反馈 | 师生对话、历次路径尝试 |

浏览器 Context 支撑独立练习；发生对话时，后台 Context 是经重放与校验的对应记录。只需这两个明确职责，不把本地每次变化等同于网络同步，也不将所有操作显示为聊天气泡。

通用 Prompt 不写 Q01 变量、答案或专属路线；缺少本步信息才追问，信息齐全就确认完成，不借旧尝试或老师给过的答案推断学生已掌握。

## Q08：对称结构与和积换元

Q08 `/1/q08/` 的目标为 `(x²+y²+6)/(x+y)`，条件为正数 x、y 且 xy=1，最小值 4 在 x=y=1 时取得。章节仅归入常规配凑，提供常规配凑与找对称结构、和积换元两条练习路径。

对称路径先分别判断交换变量后条件与目标是否不变，再定义 s=x+y、p=xy。这两个公共组件使用现有双槽位事件，但按位置校验，不能像基本不等式的两个正项那样交换。定义完成后系统展示目标化为 s+4/s 及 s≥2 的可行范围，后续继续使用 s、p，取等验证时才代回原变量。

本题的凑配步骤使用候选改写和预写的通分核对，不需要计算板。学生可通过对话提出其他思路；只有后续题目需要执行学生自定的运算、展示非预写的推导或图形时，再增加计算板。

Q08 验收：题库回归 84 项通过（6 项真实模型测试默认跳过）；单独开启 Q08 的 2 条 DeepSeek 场景均通过。覆盖两条路径错误修正、s/p 有序定义、部分证据累积、路径历史、同步失败原子性与幂等重试。浏览器走通两条路径和首次对话同步，检查 320/375 像素窄屏无页面横向溢出。模型自由解释仍非形式验证结果；验收中发现的分式改写与界的方向解释已补入本题教学说明并复核。

## Q09：实数条件下的配凑与消参

Q09 `/1/q09/` 归入常规配凑。路径列表首先展示“配凑后应用基本不等式”，其次为“消参法”，由学生选择。两条路径均先在 a、b 非零的前提下将原分式条件整理为 2a+3b=1。

配凑路径先区分 ab<0 与 ab>0；只有在正积分支中，由同号和正的加权和推出 a、b 为正，再对 2a 与 3b 定和求积。系统将 6ab 的上界 1/4 换算为 ab 的上界 1/24，取等时验证 a=1/4、b=1/6 满足原分式条件，并与所有负积情况比较。

消参路径允许保留 a 或 b，复用选择、配方/顶点和取值验证组件，保留非零限制。无需新增公共 JS、通用 Prompt 特例或计算板。题目内容在 HTML，教学判定在 q09.json。测试覆盖两种保留变量与两种二次式方法的组合、代表性错误、路径历史、失败重试，以及真实 DeepSeek 的两条对话路径。

Q01 顶点法与 Q09 消参后的上界步骤已共用二次函数展示组件。HTML 提供顶点式系数、绘图窗口、定义域及不取点，公共组件绘制抛物线、顶点和辅助虚线；推导与图像在桌面并排、窄屏上下展示。Q09 保留 a 或 b 时绘制对应函数，并显示负积区间和两个不可取值。该改动仅涉及展示，不改变教师 JSON 或作答判定。

## Q10：先识别齐次结构，再实际配式

Q10 `/1/q10/` 归入“配齐次式求最值”。题目为正数 x、y 满足 x+5y=1，求 5/x+4/y 的最小值；不带教材编号，只提供配齐次式一条路径。五步为：识别齐次结构 → 配齐次式 → 观察和积结构 → 应用基本不等式 → 验证取等。

识别步骤要求目标次数 −1、条件表达式次数 +1，系统展示乘积次数 0，不提前展示展开结果。实际配式先选择整个式子／第一项／第二项，再选择乘数；正确输入为整个式子、x+5y。系统展开成 25+25y/x+4x/y，后续两正项积为 100，原式下界为 45，在 x=1/3、y=2/15 时取到。

新组件 homogeneity 与 rewrite 沿用双槽位 fill 事件及有序校验；rewrite 的两个槽位分别限制候选域。每个范围的配式由本题 HTML 模板显示，未加入计算板。只给一项乘 x+5y 或整体乘常数 1 均保持值，但整体没有配成零次；乘 x+y 则不保持原值，教师说明区分这两类情况并提供局部展开依据。

## Q11：点选换元对象，系统同步改写

Q11 `/1/q11/` 归入“换元求最值”。题目为 a>0、b>0、a+b=2，求 2/(a+1)+4/b 的最小值；只提供换元法一条路径。六步为：换元 → 识别齐次结构 → 配齐次式 → 观察和积结构 → 应用基本不等式 → 验证取等。

换元步骤中，学生在目标式里点选要看成整体的部分（a+1 或其中的 a），被选中的块挂出新变量标签 t；下方对照表由本题 HTML 模板按所选对象展示条件、范围、目标的改写（t=a+1 时为 t+b=3、t>1、2/t+4/b；t=a 只是改名）。学生只判断换哪一块，改写由系统给出，不算学生推导。后续四步复用 Q10 的组件：乘入 (t+b)/3=1，得 2+(1/3)(2b/t+4t/b)，两项积为 8，下界 2+4√2/3；取等时 t=3√2−3≈1.24，需要在换元后的范围 t>1 内，回到原变量 a=3√2−4、b=6−3√2。

substitution 组件扩展为两种形态：未声明画板时仍是 Q08 的 s、p 定义；声明 `board` 与 `scope_boards` 时是点选换元。点选形态只有一个槽位，槽位的 `names` 决定最多换几个整体，多个对象按候选顺序用 `|` 连接，前端与后台按同一规则校验（后台把合法组合全部列为候选值）。重叠的对象（a 在 a+1 里）由画板嵌套关系判断，选一个自动取消另一个；新变量按在目标式中的位置从左到右命名，不按点击顺序，以便后续步骤模板固定使用 t、u。两个换元由 Q12 首先使用。

## Q12：两个分母同时换元

Q12 `/1/q12/` 同样归入“换元求最值”。题目为正数 m、n 满足 2m+n=6，求 1/(2m+1)+1/(n+1) 的最小值，六步与 Q11 相同。换元步骤只有两个分母可点，新变量为 x、y；两个都选才正确，得 x+y=8、x>1、y>1，只选一个时对照表展示另一个分母仍含原变量。后续乘入 (x+y)/8，得 1/4+(1/8)(y/x+x/y)，两项积为 1，最小值 1/2 在 x=y=4（m=3/2、n=3）时取到。教师说明另一种做法 1/x+1/y≥2/√(xy)、xy≤16 同样成立，并指出 m=n 不是取等条件。

## Q13：只给一项乘入定值 1

Q13 `/1/q13/` 归入“配齐次式求最值”，排在 Q10 后面。题目为 a>0、b>0、2a+b=1，求 1/a+a/b 的最小值，五步与 Q10 相同。与 Q10 相反，本题正确的作用范围是第一项：1/a 负一次、a/b 已是零次，只给 1/a 乘入 2a+b=1（相当于把分子的 1 换成 2a+b），得 2+b/a+a/b；给整个式子乘会让第二项变成一次。后续两项积为 1，原式≥4，在 a=b=1/3 时取到。

识别步骤因此判断三个次数：第一项、第二项、条件表达式。homogeneity 的格数由 `slot_labels` 的数量决定（未写时仍为两格），前后端按同一格数校验 fill 下标和完整性，状态中的格子按需补足；只有两格时才显示相乘后的次数。`slot_shapes` 可指定各格的方框或圆圈，本题目标两项用方框、条件表达式用圆圈。

## Q14：直接乘 1，或先换元再配齐次

Q14 `/1/q14/` 归入“配齐次式求最值”，排在 Q13 后面。题目为 x>0、y>0、1/x+4y=1，求 x+1/y 的最小值。按 x、y 判断次数时，目标和条件表达式都含一次项和负一次项，Q10 的次数论证不能直接使用，因此提供两条路径，学生先选择。

“直接乘 1”排在前面，四步：给整个式子乘 1/x+4y，展开为 5+4xy+1/(xy)，依据是 x 与 1/x、1/y 与 4y 两两相乘为常数；随后 4xy 与 1/(xy) 积为 4，原式≥9，在 xy=1/2 即 x=3、y=1/6 时取到。“先换元再配齐次”六步：点选 1/y 设为 t，得目标 x+t（正一次）、条件 1/x+4/t=1（负一次），之后与 Q10 相同，展开为 5+4x/t+t/x，取等时 t=2x，得 x=3、t=6。两条路径共用完成页，完成后可切换到另一条路径再做一遍。

两条路径的模板以 `direct-`、`sub-` 前缀区分，节点 id 沿用各组件的常用名。换元画板中 1/y 是分式整体，内部的 y 可单独点选，沿用点选换元的嵌套判断。教师说明写明两条路径等价，学生在一条路径中提出另一条的思路时，认可成立并提示用切换路径尝试。未改公共 JS。


### Q14：有限组合的计算预览

Q14 两条路径的配式步骤已加入预先验证的组合计算：选择时展示尝试，确认后展示计算过程；错误组合也可展开，但分别判断等价性和目标达成。18种组合的展示归本题 HTML，公共 runtime 仅按作用范围与乘数查找模板。`attempt_calculations` 为页面展示配置，不进入教师 JSON；点选和计算展示均不调用 API。正确组合沿用完成态，改选后清除旧结果。数学推导与自然语言反馈分区，不新增独立交互组件，也不视为已实现自由输入的实时计算板。

## Q15：先拆项，再按 Q13 的方式局部配式

Q15 `/1/q15/` 归入“配齐次式求最值”，排在 Q14 后面。题目为 a>0、b>0、a+b=1，求 (b+1)/a+(a+1)/b 的最小值，五步与 Q13 相同。系统先把原式拆成 (b/a+a/b)+(1/a+1/b)，学生判断第一组零次、第二组负一次、条件表达式 a+b 正一次；配式步骤只给第二组乘入 a+b，得 2+2b/a+2a/b。后续两项积为 4，原式≥6，在 a=b=1/2 时取到。

拆项由系统展示，不作为学生判断：识别步骤的画板在三格次数上方加一行 `.deg-split`；配式画板的两个按钮就是拆出的两组。教师说明认可“把原分子中的 1 换成 a+b”与本步等价，也认可直接对原两项用基本不等式、再结合 ab≤1/4 的思路。只新增 `.deg-split` 样式，未改公共 JS。

Q14 的计算展示依据 `PracticeContext.confirmedPair(view)`：仅当前尝试、当前路径、当前步骤的最后一次 UI 动作为提交，且恢复出的组合仍等于当前选值时显示。不能依赖 `state.feedback`，因为真实对话会清空临时反馈。提问/提示保留计算；改选、改回但未重确认、切换路径均不复用旧计算。

## Q16：消参、分式分离、凑配表达式

Q16 `/1/q16/` 是新建分组“消参法求最值”的第一题（原预留名“条件消元”，全题库统一改称消参法；Q01、Q09 的路径名和步骤标题同步改名，老师说明注明“条件消元”为同义说法）。题目为 x>0、y>0、x+2y+xy-7=0，求 x+y 的最小值，只提供消参法一条路径，六步：消参 → 分式分离 → 凑配表达式 → 观察和积结构 → 应用基本不等式 → 验证取等。

消参用 choice 选出 x=(7-2y)/(y+1)，系统补出 0<y<7/2。分式分离练“用分母表示分子”：在 7-2y=□·(y+1)+○ 中填 -2 和 9，系统再逐项除以分母得 x+y=y+9/(y+1)-2；一般多项式分式可用除法写成商加余式除以分母；分子次数较低时商为 0，不能直接取倒数或只除以分母中的某个一次式，换元 t=y+1 在老师说明中认可为等价做法。凑配表达式与 Q06 相同，选 (y+1)+9/(y+1)-3。后续积为 9，x+y≥3，在 x=1、y=2 时取到。老师说明另外认可用 x 表示 y、因式分解 (x+2)(y+1)=9 两种思路。

分式分离使用新增的公共组件 `fill`：HTML 画板写出公式，用 `data-fill="i"` 放置槽位；前端与后台按位置校验，与 homogeneity、symmetry 同属有序组件。它只在预写公式中点选候选值，不是自由输入。

Q16 的双槽位 `fill` 复用 `attempt_calculations`：25 个候选组合均有映射，24 个错误组合展示实际展开及系数、常数核对；使用“不恒等”而非断言所有取值都不相等。未确认画板以问号等号标记尝试。计算在提问后保留，改选后清除，正确组合使用完成态。

## Q17：把 m² 看成整体消参，再分式分离

Q17 `/1/q17/` 归入“消参法求最值”，排在 Q16 后面。题目为 5m²n²+n⁴=1，求 m²+n² 的最小值（答案 4/5），只提供消参法一条路径，五步：消参 → 分式分离 → 观察和积结构 → 应用基本不等式 → 验证取等。

消参用 choice 选 m²=(1-n⁴)/(5n²)，干扰项漏掉系数 5、分子符号写反，各有整理核对预览；完成态补出 n≠0、0<n²≤1，并说明为何消 m²（m 只以 m² 出现且为一次，反过来要解关于 n² 的二次方程）。分式分离是一次合并填空：m²+n² ≟ □·1/n² + ○·n²，填 1/5、4/5；分母是单项式，逐项相除后与 n² 合并，积已固定为 4/25，不需要再凑配。后续 m²+n²≥4/5，在 n²=1/2、m²=3/10 时取到。

题目没有给出 m、n 为正，老师说明不得默认正数；认可因式分解 n²(5m²+n²)=1、换元 a=m²、b=n² 等等价思路。

分式分离沿用 Q16 的 `fill` 与 `attempt_calculations`：25 个组合均有映射，24 个错误组合把所填两项通分为 (5□+5○n⁴)/(5n²)，与原式 (1+4n⁴)/(5n²) 比较分子常数项和 n⁴ 系数。不直接展示 1/(5n²)+4n²/5，以免替学生完成本步。未改公共 JS/CSS。

## Q18：配因式后整体消参

Q18 `/1/q18/` 归入“消参法求最值”，排在 Q17 后面。题目为正数 a、b 满足 2ab+2a+b=3，求 1/(2a+1)+1/b 的最小值（答案 5/4），只提供一条路径，五步：配因式 → 消参 → 观察和积结构 → 应用基本不等式 → 验证取等。

配因式是单格 `fill`：在 (2a+1)(b+1)=□ 中填 4（候选 2–6）。单格通过 `attempt_calculations` 一层映射展示展开核对，比较乘积4与所填值；未确认使用问号等号，避免把尝试显示为已证等式。消参用 choice 选 1/(2a+1)=(b+1)/4，干扰项 4/(b+1)（求成 2a+1 本身）、(b+1)/3（沿用原条件的 3）各有整理核对预览。完成态由系统补出 0<b<3、拆项 b/4+1/b+1/4，并说明为何用 b 表示整体 2a+1，而不解出 a。后续 b/4 与 1/b 积为 1/4，原式≥5/4，在 a=1/6、b=2 时取到；常数 1/4 不参与基本不等式。

老师说明认可直接解出 a=(3-b)/(2(b+1)) 和换元 x=2a+1、y=b+1（xy=4）。学生若直接对 1/(2a+1) 与 1/b 用基本不等式，先认可运算成立，再解释右端随变量变化，尚未求得定值最优下界。对三项 b/4、1/b、1/4 的基本不等式也应认可，但三项无法同时取等。公共 Context/runtime 扩展了单格计算反馈，CSS 未改。

### Q18 单格配因式核对

单格 `fill` 复用 `attempt_calculations` 一层映射（值 → HTML模板ID）；双格保持二层映射。确认错答后展示实际展开值与所填值的比较，未确认使用问号等号。Context 的单格组合恢复兼容第二格空字符串；提问保留计算、改选清除且改回需重新确认。此能力仍是 fill 的静态计算反馈，不增加独立组件。

## Q19：消参、分式分离、凑配表达式

Q19 `/1/q19/` 归入“消参法求最值”，排在 Q18 后面。题目为 a>0、b>0、9a+b=ab，求 a+4b 的最小值（答案 49），只提供消参法一条路径，固定消 b，六步与 Q16 相同：消参 → 分式分离 → 凑配表达式 → 观察和积结构 → 应用基本不等式 → 验证取等。

消参用 choice 选 b=9a/(a-1)，干扰项 9a/(a+1)（移项未变号）、(a-1)/(9a)（除反）各有整理核对预览；完成态补出 a≠1、a>1 与 a+4b=a+36a/(a-1)。分式分离是双格 `fill`：36a ≟ □·(a-1)+○，填 36、36，候选 -36、9、35、36、37；24 个错误组合经 `attempt_calculations` 展开，比较 a 的系数与常数项。凑配表达式用 choice 选 (a-1)+36/(a-1)+37，干扰项“未凑配”（积不固定）与“常数未调整”（+36，不等价）各有展开核对预览。后续 (a-1) 与 36/(a-1) 积为 36，a+4b≥49，在 a=7、b=21/2 时取到；常数 37 不参与基本不等式。

最初把分式分离与凑配合成一次填空，评审后按 Q16 拆成两步：两个动作的依据不同（前者是恒等除法，后者是为定积配对并补常数），分开后每步反馈更明确。

## Q20：消参后先判断两项为正

Q20 `/1/q20/` 归入“消参法求最值”，排在 Q19 后面。题目为 m>2、n>1、3m+3n=mn+7，求 m+2n 的最小值（答案 13）。只提供消参法一条路径，固定消 m，共 7 步：消参 → 分式分离 → 凑配表达式 → 判断两项为正 → 观察和积结构 → 应用基本不等式 → 验证取等。

消参用 choice 选 m=(3n-7)/(n-3)，干扰项 (3n+7)/(n-3)（移项未变号）与 (3n-7)/(3-n)（只翻一半符号）各有代回核对预览。分式分离是双格 `fill`：3n-7 ≟ □·(n-3)+○，填 3、2，候选 -7、-2、2、3、7；24 个错误组合经 `attempt_calculations` 展开，比较 n 的系数与常数项，不直接给出答案。凑配表达式用 choice 选 2(n-3)+2/(n-3)+9，干扰项“未凑配”与“常数未调整”各有核对预览。

与 Q16–Q19 不同，本题 n 的范围不能直接从已知读出：n>1 不能保证 n-3>0，要由 m>2 推出 n>3。因此“判断两项为正”作为独立 choice 步骤（字段 positive_basis），放在凑配之后、结构之前。此时学生已看到要配对的两项 2(n-3) 与 2/(n-3)，判断“为什么为正”有明确对象；放在消参之后则缺少判断目标。选项为“由 m>2 推出 n>3”（正确）、“由 n>1 即可保证”、“无法保证”。完成态补出反向核对：n>3 时 m=3+2/(n-3)>3>2，两个条件都满足。

后续两项积为 4，m+2n≥13，在 n=4、m=5 时取到；常数 9 不参与基本不等式。老师说明认可消 n 以及配因式 (m-3)(n-3)=2。未改公共 JS/CSS，也没有题目专属 Prompt。

## Q21：双换元与待定系数

Q21 `/1/q21/` 归入“换元求最值”，排在 Q12 后面。题目为 a>0、b>0、1/(4a+b)+1/(a+2b)=3，求 5a+3b 的最小值（答案 4/3）。只提供换元法一条路径，共 7 步：双换元 → 用新元表示目标 → 识别齐次结构 → 配齐次式 → 观察和积结构 → 应用基本不等式 → 验证取等。

双换元沿用 Q12 的点选 `substitution`（names 为 x、y），但点选对象在条件式里：把两个分母记为 x=4a+b、y=a+2b，条件化为 1/x+1/y=3。只换一个时预览显示另一个分母仍含 a、b。用新元表示目标是双格 `fill`：5a+3b ≟ □·(4a+b)+○·(a+2b)，候选 1–5，答案 1、1；24 个错误组合经 `attempt_calculations` 展开，比较 a、b 的系数，不直接给出答案。本题系数恰好为 1，但待定系数的做法可延续到系数不为 1 的变式。

之后与 Q12 相同的配齐次链路，只是次数方向相反：目标 x+y 为正一次，条件表达式 1/x+1/y 为负一次，给整个式子乘 (1/3)(1/x+1/y)=1，展开得 2/3+(1/3)(y/x+x/y)。取等 x=y=2/3，回代 a=2/21、b=2/7。

换元后 x、y 实际还需满足 2x>y、4y>x（由 a=(2x-y)/7>0、b=(4y-x)/7>0）。不等式对所有正数成立，所以不单独设范围步骤，只在验证取等时回代检查 a、b 为正，并在完成态说明取等点满足这两个条件。老师说明认可先解出 a、b 再代入、不换元直接乘 1，以及 3=1/x+1/y≥2/√(xy) 后再用 x+y≥2√(xy) 的两次放缩。未改公共 JS/CSS。

## Q22：双换元后用待定系数改写条件

与 Q21 对照：换元对象在目标式的两个分母里（同 Q12），新变量记为 a、b，避免与原变量 x、y 混淆；换元完成时系统补出 a=x+(x-y)>0、b>0，不单独设正负步骤。待定系数改为作用于条件：4x+3y ≟ □·(2x-y)+○·(x+2y)，答案 1、2，需要真正解方程组；24 个错误组合展开后比较 x、y 的系数，其中 y 的系数可能为 0 或负数。次数方向同 Q12（目标负一次、条件正一次），a+2b 本身等于 1，直接乘入，展开得 5+2b/a+2a/b，两项积为 4。

## Q24：先换元再逐项分式分离

## Q30：构造对称或消元求最小值（两条路径）
