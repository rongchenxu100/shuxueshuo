# 全站手机号登录与题目学习标记计划

日期：2026-10-03。状态：第一阶段登录与登出已实现并通过本地模拟测试，阿里云真实短信待配置联调，尚未上线；AI 登录限制和学习标记待实施。运行方式见[本地登录测试说明](site-login-local-testing.md)。

## 1. 已确认的范围

- 主站共用手机号验证码登录，使用已有阿里云短信服务。首次验证成功自动创建账号。
- 第一阶段包含登出功能，并支持本地模拟短信测试及阿里云真实短信联调。
- 未登录可以浏览题库、打开题目并完成本地点选练习。
- AI 对话和 AI 提示必须登录后使用。
- 游客完成一道交互题后，提示“登录后保存进度”；登录成功后保存这道题的学习标记。
- 已登录学生完成一道题后自动保存，并可自行选择“熟练掌握”或“需要再次练习”，也可清除选择。
- 当前只保存每个学生在每道题上的“是否练习过”和一个学习状态字段，不保存题目版本、当前解法、当前步骤、填写答案、已完成步骤或练习历史，不提供断点续练。
- 知识图谱及练习过程映射后续实施。当前学习标记无法还原历史答题过程。

本文是登录和个人学习标记的当前范围依据；旧的《基本不等式章节题库：首版设计与实施计划》中关于进行中、错误统计、游客不合并等规划，不用于本次实施。

## 2. 最小学习数据

以 `(user_id, problem_id)` 唯一确定一条记录，业务字段只有：

| 字段 | 含义 | 更新方式 |
| --- | --- | --- |
| `practiced` | 是否练习过 | 完成一道题的交互流程后置为 true |
| `learning_status` | 学习状态 | 学生自行选择：`unmarked`（未标记，默认）、`mastered`（熟练掌握）、`needs_review`（需要再次练习） |

无记录时按 `practiced=false`、`learning_status=unmarked` 展示；打开页面、做了一部分或发送 AI 消息不自动标记为练习过。完成判定使用现有题页的完成事件，不新增过程持久化。

熟练掌握和需要再次练习是同一个字段的互斥取值，不分别存储布尔字段；清除选择时设为 `unmarked`。再次完成练习仅更新 `practiced`，不能覆盖学生已设置的 `learning_status`；重复完成请求不增加记录。重新练习不清除曾练习过的事实。

题目使用全站稳定且不重名的 ID；不同章节的“第 1 题”不能共用一个 ID，复用或明确映射现有 lesson/catalog 标识，不以题号或任意 URL 直接作主键。后端校验题目存在，学生身份从登录会话取得，不接受浏览器指定他人的 `user_id`。

这些记录用于个人学习标记，不作为考试成绩或后端认证的能力评估。首版不为了验证“练习过”而上传完整答题过程。

## 3. 页面交互

1. 公共登录组件展示登录入口或当前账号，所有主站题库共用。
2. 游客可以直接做题；完成后显示“登录后保存进度”。
3. 点击后在当前页面打开手机号验证码登录框，保留本页完成标记。
4. 登录成功后，提交本页完成标记；只有接口确认成功才显示“已保存”。保存失败保留待保存标记并支持重试，不丢弃已有练习结果。
5. 已登录时，完成练习自动保存；学习状态采用单选，提交明确的 `learning_status` 枚举值，清除选择提交 `unmarked`，不使用反转接口，避免重试改变原意。
6. 题库页面读取本人学习标记并展示；换设备登录后可以看到同样的标记，但打开题目仍从头练习。
7. 游客点击 AI 提问或 AI 提示时先登录，保留尚未发送的问题；登录后继续原操作。
8. 登录过期时，受保护请求返回 401，前端提示重新登录；不能自动重复发送已成功的 AI 请求。
9. 退出或切换账号时清除前端旧账号标记缓存、AI 会话引用和待发送账号操作，避免串号。

公共账号入口提供“退出登录”。后端撤销当前登录 session，浏览器清除对应 Cookie，页面恢复游客状态；已保存的学习标记留在数据库中。本次退出只影响当前登录会话，不实现“退出所有设备”。重复退出或会话已过期时仍可完成清理；退出请求失败时提示重试，不把仅清除页面显示当作服务端已退出。退出后到达的旧账号请求响应不能重新填回页面。

游客登录衔接只处理当前页面的待保存标记，不实现跨页面游客历史或复杂数据合并。账号已有标记时，完成操作只把 `practiced` 置为 true。

## 4. 在哪里检查 session

### 当前部署入口

- `deploy/nginx/shuxueshuo.conf`：主站静态页面由 Nginx 直接返回，`/api/` 转发到 `127.0.0.1:8000`。
- `server/shuxueshuo_server/main.py`：生产 FastAPI 入口，注册教学 API 等路由。
- `server/shuxueshuo_server/tutor_demo/api.py`：现有 `/api/tutor-demo` 路由，当前没有学生登录校验。
- `site/assets/practice/runtime.js`：公共交互运行时，本地练习与按需 AI 请求的接入点。

### 计划采用的检查位置

在 FastAPI 的受保护路由上使用统一的 `require_user` 依赖：读取 Cookie，查询登录会话，检查有效期和撤销状态，取得 `user_id`。无有效登录返回 401，有效登录才进入业务处理。可在整组 APIRouter 上挂载登录依赖，业务处理函数再取得当前用户以检查数据归属。

无需写一个拦截所有网页 URL 的登录跳转规则。公开页面和登录接口允许匿名访问，AI 与个人数据接口明确要求登录。前端弹框用于交互体验，不能替代后端检查。

| 路由 | 登录要求 | 用途 |
| --- | --- | --- |
| `/`、题库页、题目页、静态资源 | 公开 | 浏览和本地练习 |
| `POST /api/auth/sms/send`（拟新增） | 公开，受短信发送限制 | 发送验证码 |
| `POST /api/auth/sms/verify`（拟新增） | 公开，受核验限制 | 核验并创建登录会话 |
| `GET /api/auth/me`（拟新增） | 可匿名，返回游客或当前用户 | 公共组件查询登录状态 |
| `POST /api/auth/logout`（拟新增） | 可幂等退出 | 撤销当前会话并清除 Cookie |
| `/api/learning/marks` 及单题读写接口（拟新增） | 必须登录 | 读取和修改本人标记 |
| `/api/tutor-demo/sessions` 及会话读取、事件接口 | 必须登录 | 创建、读取和使用本人的 AI 教学会话 |
| `/api/health`、现有微信分享配置 | 保持公开接口语义 | 健康检查与分享支持 |

Nginx 继续负责 HTTPS、静态资源与 API 转发，不查询学生 session 数据库。新增校验不替代 Studio `/api/product/` 现有权限边界；学生登录不授予后台权限。本次不接入 Studio 跨子域单点登录。

### 请求流程

```text
打开题目页 → Nginx 返回静态 HTML → 可以直接练习

点击 AI / 保存标记
    → 浏览器请求同源 /api/...，携带登录 Cookie
    → Nginx 转发到 FastAPI
    → require_user 查询登录会话
        → 无效：401 → 前端打开登录框
        → 有效：取得 user_id → 检查数据归属 → 执行业务
```

AI 教学 `session_id` 和登录 session 是两种不同对象。登录 session 表示“你是谁”；教学 session 表示“当前是哪次教学对话”。教学会话创建时绑定当前 `user_id`，读取和发送事件时检查所有者。只知道教学 session ID 不构成访问权限。

## 5. 登录会话与短信

验证码核验成功后，后端查找或创建用户，生成不可预测的随机登录 token；数据库保存 token 摘要、用户 ID、有效期与撤销状态，原始 token 通过 `Set-Cookie` 交给浏览器。

生产 Cookie 使用 `HttpOnly; Secure; SameSite=Lax; Path=/`。浏览器在符合 Cookie 范围的请求中自动携带它，页面 JS 不读取 token；公共组件通过 `/api/auth/me` 取得脱敏用户信息。退出时撤销服务端会话并清除 Cookie。登录有效期做成配置项，实施时确定默认值。

首版建议统一以 `https://shuxueshuo.com` 为主站地址，将 `www` 重定向到该地址，使用仅主站有效的 Cookie，不向 Studio 等所有子域扩散。主站所有路径共享登录；跨设备需分别登录同一手机号。本地开发与测试方式见第 7 节。

复用现有 PostgreSQL 与迁移机制持久保存用户、登录会话和学习标记；学生用户不能套用工作台固定身份。优先复用已有用户主体，手机号登录身份以唯一约束关联用户，不自动添加工作台成员权限。无需为首版额外引入 Redis。服务重启后登录和学习标记保留；现有教学对话仍可保持临时会话，不承诺恢复。

已确认使用阿里云普通 `SendSms`，本服务生成和核验验证码。验证码挑战保存受密钥保护的摘要、有效期和尝试次数，原子完成核验与消费，防止重复兑换登录会话；真实短信验证码不作为明文持久记录。模拟短信仅写入本机私有测试目录。

实现时一并处理手机号/IP 发送频控、验证码有效期与错误尝试上限、全站短信发送预算，以及修改数据请求的 CSRF 防护（校验可信 Origin，拒绝不可信来源）。阿里云凭据仅由后端环境配置读取；手机号、验证码和 Cookie 不写入公开页面或常规日志。

## 6. 三阶段实施与验收

| 阶段 | 实施内容 | 验收结果 |
| --- | --- | --- |
| 1. 手机号登录与登出 | 确认阿里云接口、签名和模板；完成用户与会话迁移、发码、核验、当前用户查询、退出及全站公共登录组件 | 登录后切换主站页面仍保持身份；退出后旧凭证失效；支持本地模拟短信和真实短信联调 |
| 2. AI 登录限制 | AI 路由接入统一登录依赖与会话所有者检查；未登录提问或请求 AI 提示时弹出登录框 | 游客可点选练习，但直接请求 AI 接口也会被拒绝；登录后可继续提问，不能访问其他学生的教学会话 |
| 3. 学习标记 | 完成题目后的登录提示、登录后自动保存、学习状态单选及题库读取 | 换设备或重启服务后标记仍在；不同学生和不同题目的标记互不影响 |

各阶段补充验证：第一阶段覆盖验证码过期、错误次数限制、重复核验、唯一手机号并发注册、session 过期与撤销、重复退出及账号切换；第二阶段覆盖生产与独立教学开发入口，验证绕过前端也不能匿名调用 AI；第三阶段覆盖重复提交、保存失败重试、学习状态切换与清除、拒绝非法枚举值、完成不覆盖学习状态和不同章节同题号隔离。

完成第三阶段后验收完整流程：游客完成 → 登录 → 保存 → 返回题库；退出再登录、换设备及服务重启后标记仍在；失效 session 返回 401；未登录始终可本地练习；题页不恢复步骤和答案。

开发按三个阶段推进，首次正式发布建议将阶段 1、2 一起上线，使登录入口与 AI 登录要求形成完整体验；阶段 3 可随后发布。每次发布包含对应数据库迁移、后端和主站静态文件；如果统一 `www` 地址，还需更新 Nginx。只有前端登录弹框不能视为完成登录功能。

## 7. 本地开发与测试

本地可以完整测试登录和登出，无需先部署生产网站。优先提供页面与 API 同源的本地入口，使用独立开发数据库和测试账号，不连接生产用户数据。

| 模式 | 用途 | 配置与边界 |
| --- | --- | --- |
| 模拟短信 | 日常开发、自动化测试 | 显式启用测试短信适配器，不发送真实短信；通过测试夹具或仅本地测试渠道取得验证码，继续经过正常的核验、session 创建和退出流程 |
| 阿里云真实短信 | 验证实际短信投递与登录链路 | 在本地后端配置阿里云凭据、签名和模板，向开发者自己的手机发送验证码；按真实服务计费 |

模拟短信只替换发送／验证码服务适配器，不提供绕过登录校验的万能验证码。生产环境禁止启用模拟模式，配置错误时应拒绝启动；公开 API 不返回验证码。测试覆盖发送限制、核验错误和过期、验证码一次性使用、session 创建及失效。

真实短信登录采用本地后端主动调用阿里云发送／核验接口的方式，不依赖短信投递状态回调，因此本地联调不需要公网回调地址，但需要能访问阿里云接口及有效的服务配置。

本地 HTTP 与生产 HTTPS 分开配置 Cookie：本地开发可关闭 `Secure`，仍保留 `HttpOnly`、`SameSite=Lax` 和 `Path=/`；生产必须启用 `Secure`。开发配置不能带入生产。测试时统一使用 `localhost` 或 `127.0.0.1`，不要混用不同主机名。

若保留 8765/8766 跨端口开发方式，需要前端显式携带凭据，后端允许精确的开发 origin 和 credentials，并让 auth、教学、学习标记接口共享会话存储；优先采用同源入口减少此类配置差异。

本地验收覆盖：发码 → 登录 → 切换题页仍登录 → 使用 AI（阶段 2）→ 保存标记（阶段 3）→ 退出 → 旧 Cookie 请求被拒绝。使用两个独立浏览器上下文验证用户隔离，测试账号切换及退出后的迟到响应不会显示旧账号数据。再通过一次真实短信联调验证阿里云接入；模拟测试通过不代表真实投递已验证。
