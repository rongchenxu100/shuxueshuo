## 1. 求解与讲解的协作

<a id="family-rules"></a>

### 1.1 一个 Family，多种讲解规则

基本不等式统一使用一个 `basic_inequality` Family，容纳直接应用、整块整理、配齐次、换元、消元和连续估计等策略。

| 层级 | 职责 |
|---|---|
| 求解 LLM | 参考 Family 选择路线、绑定输入，按各 Method 契约提供参数 |
| Method | 验证或计算数学结果，提供讲解片段、依据、依赖和已绑定视觉 |
| Family | 提供求解参考策略，并声明启用的注册 rule ID 与配置 |
| 讲解 rule | 根据成功执行记录判断适用性，拆分/合并片段、组织文字与视觉、生成路线概览 |
| 通用讲解层 | 调度规则、处理冲突与锁定、校验覆盖和依赖，组装 LessonIR |
| Lesson LLM | 查看完整上下文，组织 rule 未锁定的开放材料 |

Family 引用注册逻辑 ID，不填写任意代码或文件路径。Family 标签或 LLM 自报策略不能代替数学依据。规则按已验证结构触发，不按题号分支；前端只展示绑定结果，不重新判断数学。

Method 数量、调用次数和学生步骤数分别计算。一个 Method 可多次调用，一次调用可提供多个教学片段；片段只承担展示职责，不创建数学对象或状态版本。公共调用外壳保留 `step_id`、`capability_id`、`args` 和可选 `parameters`，推导参数由 Method 自有 schema 校验；LLM 参数未经验证不能成为事实。

<a id="lesson-llm"></a>

### 1.2 rule 先组织并锁定，LLM 编排开放材料

与 [Lesson Scope LLM Authoring](lesson-scope-llm-authoring-vnext-design.md) 协作：

```text
成功执行 → ExplanationSnapshot / 公共教学片段
→ Family rule 匹配、组合、锁定
→ 固定步骤与开放材料一起投影给 Lesson LLM
→ 校验锁定边界、覆盖与依赖，注入固定步骤和 verified conclusions
→ LessonIR → 确定性视觉生成
```

- Method 声明不可切割的推导片段、先后依赖与组件。rule 按准确对象身份、状态版本和实际输入依赖拆并，不能仅凭调用相邻合并。
- rule 锁定步骤的边界、归属、顺序、位置、标题、正文、数学内容和视觉。Lesson LLM 只保留其引用，无权改写、移动、拆并、删除或吸收相邻材料；原对象由代码注入。
- Lesson LLM 可见固定步骤的完整内容，只能在同一 Scope/Goal 内、不跨锁定边界的连续开放区间编排，沿用局部 `source_steps` 与内部 authority 映射。不得跨私有 Macro 边界。
- 规则可作用于整条路线、局部调用组或单次调用。作用范围不冲突时组合；争用材料时按声明优先级处理，同优先级歧义须报告并回退。
- 每个必讲片段恰由一个学生步骤负责。路线概览只读引用后续证据，不重复计算详细推导覆盖，也不伪装成 runtime 步骤。
- 动态 schema、authority 映射与 validator 共同检查锁定、连续性和完整覆盖；正式字段待实现时确定。结构校验不等于证明每句开放文案的数学语义。
- 无匹配规则时沿用现有 Lesson LLM 路径；全部材料锁定时可跳过 Lesson LLM。输出非法或 LLM 不可用时，确定性 fallback 仍须保留已锁定结果。

观察步骤说明实际推导为什么有效。不得用“变量数减等式数”决定取等关系数或基本不等式应用次数，也不得凭某种结构不明显就断言其他方法不可行。

### 1.3 数学表达式优先的公开协议

LLM-facing 协议只要求模型提供题面可读的数学表达式，不要求模型构造内部 AST、Method 参数对象或操作标签。`capability_id` 是路由元数据；所有表达式型 Method 的 LLM-facing 候选只使用 `math` 或 `steps[].math`。前提选择、目标角色、取等条件和还原分支由编译器从当前 Scope 与表达式链推导。

例如，应用二元基本不等式时，模型可以提交完整关系：

```json
{
  "math": "a+b+1≥2√(ab)+1"
}
```

题设中的 `a>0`、`b>0` 由当前 Scope 绑定，不要求模型重复抄写；标准 AM-GM 的 `a=b` 由代码生成并验证。模型不填写 `term1`、`term2`、`operation`、`bound_fact_id` 等内部字段。Parser 通过左右表达式树的公共部分和局部差异，识别 `a+b≥2√(ab)`；Runtime 再验证正性、公式模板、方向、定义域和取等条件，成功后生成内部 `amgm_bound` Canonical Fact。无法唯一识别或无法证明正性时必须 fail closed，并返回结构化诊断供 repair 使用。

三层职责固定如下：

| 层 | 允许内容 | 禁止内容 |
|---|---|---|
| LLM 输出层 | `a+b≥2√(ab)`、`u=x²`、`x=±√u`、完整等价式链 | `term1`、`term2`、内部 AST、Runtime Fact ID |
| Parser 层 | 保留原文和 source path，构造表达式 AST，做局部树差异和关系解析 | 把未验证候选直接当作事实 |
| Runtime 层 | 验证模板、正性、定义域、取等和可达性，生成 Canonical Fact | 要求 LLM 暴露内部实现记法 |

这条协议适用于全部 8 个 Method：M01、M07、M08、M09、M11、M12、M13、M14。它们都可以接收 LLM 提供的直接数学表达式；区别只在于 Method 是验证候选表达式、验证表达式与可行域的关系，还是根据已验证表达式计算唯一结果。`using`、`transformed_target`、`equality`、`restore` 等只作为 Runtime 内部推导字段，不进入 LLM-facing 协议。内部仍可使用 `angle`、`amgm_bound` 等 AST 或 Fact 类型，但它们不能成为新的抽取或修复示例。

| Method | LLM 提供的数学表达式 | 代码负责的确定性工作 |
|---|---|---|
| M01 | 完整等价式链 | 逐步等价、定义域和条件引用验证 |
| M07 | 换元定义、改写后的条件/目标、还原关系 | 映射、可行域、分支和还原验证 |
| M08 | 消元关系、代入后的目标和范围 | 除法依据、代入等价性和剩余约束验证 |
| M09 | `s=x+y`、`p=xy` 及转换/还原表达式 | 对称性、判别式和实根可行性验证 |
| M11 | 完整不等式关系及可选取等式 | 正项识别、公式模板、方向和取等验证 |
| M12 | 配方式、下界关系及取等式 | 非负平方项、参数前提和界的可取性验证 |
| M13 | 候选取等关系、参数化还原和原题代回表达式 | 联立、合法分支、可达性和原题验算 |
| M14 | 已验证的一元不等式和变量域 | 代码计算精确解集；LLM 不填写根或区间答案 |

M14 仍然属于表达式优先协议：LLM 提供的是待求解的数学不等式和作用域，不能把“代码计算结果”误解为让 LLM 填写内部结构。M13 的表达式候选也必须经过代码闭合，不能因为表达式形式正确就直接成为最终取等事实。

### 2.1 M01：完整等价整理

M01 是由 LLM 填写推导的空 Method，代码不负责寻找变形路线。覆盖整块改写、通分与整式除法、统一底数、整体/局部配齐次、带前提的根式或倒数形式整理。

- 一次调用验证完整式链及代码从表达式差异推导出的已有条件，只提交同对象的最终状态；中间式留在 trace 中，可供 rule 分步展示。q24 的分式整理与局部配齐次属于一次调用。
- 乘入定值条件时保留比例因子与旁置常数。辅助展示 `2T=…`、`T²=…` 或 `1/T=…` 必须来自已验证关系，不能把 T 替换为另一个极值目标。
- 验证定义域、分母非零、幂与根式适用前提。次数分析须指定变量及实际处理部分：q24 的倒数和、q27 的线性部分、q31 括号内关于 a、b 的部分。
- 可以整理中间下界对象，但原目标与下界间仍保留不等式关系。q31 两段整理被 M11 隔开，必须分别调用 M01。
- 实现基线仅覆盖 q08 有理式及整数幂整理前缀；实指数、带前提根式、后续组合讲解需扩展验证能力。

### 2.2 M07、M08、M09：变量体系与可行性

**M07** 支持平方、积整块、仿射及根式换元。保存精确范围、原条件和还原关系；非一一映射不编造单值逆函数。q12 保留平方换元的正负分支，q24 保留 u,v>1，q25 验证 a,b>1 与消分母依据，q26 保留 t>√2 和正支还原，q27 保留耦合约束 u>1、v>u−1。换元用于中间下界时仍须保留不等式依赖。

**M08** 首轮限条件对指定消元变量为一次式，记录除法非零前提，把所得关系代入目标和可行性条件，保存原变量还原及范围。q27 备选路线需要先验证有理条件消分母，不能据此宣称首轮支持任意有理条件。

**M09** 对实变量建立 `s=x+y,p=xy`，验证对称表达式的转换及 `Δ=s²−4p≥0`，提供根 `(s±√Δ)/2` 的还原关系。原变量为正时同时保留 s>0、p>0，判别式单独不足以保证正根。M13 负责结合全部原条件验证可达性。

### 2.3 M11：求界及有限目标对应

M11 的公开输入是一条直接数学不等式，代码从完整前后式中定位局部变化，不要求 LLM 声明两个正项。首轮先支持可证明的二项模板：

```text
U+V≥2√(UV)
kU+V≥2√(kUV)  （k>0）
```

解析流程为：

1. 解析左右表达式并保留展示树；
2. 展平安全的加法节点，匹配左右两侧未改变的公共项；
3. 从变化区域恢复 `U+V` 与 `2√(UV)`；
4. 用已绑定条件证明 `U>0`、`V>0` 及根式定义域；
5. 验证不等式方向、模板等价性和等号条件 `U=V`；
6. 将局部关系重新绑定到完整目标，生成 `amgm_bound` Fact、proof 和 source path。

例如 `a+b+R≥2√(ab)+R` 的公共部分是 `R`，局部关系是 `a+b≥2√(ab)`；`3x+4y+R≥2√(12xy)+R` 则恢复 `U=3x`、`V=4y`，并由 `x>0,y>0` 证明正性。无法唯一定位两个项、无法证明正性或超出注册模板时，不猜测、不自动搜索其他路线，直接返回带步骤号、前后表达式和可见条件列表的结构化诊断，要求 LLM 补充或重写直接数学关系。

M11 提供正项与和/积关系的识别片段，再提供公式应用、目标对应及取等片段。和或积可以仍含变量；第一次应用可以只得到含变量的界，后续调用绑定这一结果继续估计。

允许的已验证目标对应包括常数平移、正系数或正值表达式缩放、正数倒数、非负主值平方根及其有限组合。每一步保留符号依据、界方向和等号条件；倒数所用的界必须为正，开方所用的界必须满足非负前提。它不扩展为任意单调函数求解器。

完整目标中未参与配对的部分可含变量或负项，如 q21 的 −8ab；直接化简可随公式应用验证。求界产生不等式关系，不能把原目标等价更新为下界。识别出的正项、定和/定积及对应关系均来自成功记录，不由 rule 或前端推测。

### 2.4 M12：二次式求界

M12 负责配方后的界与取等依据。M01 只验证等价变形；M14 则计算不等式解集，三者输出语义各异。

- q21：对 p>0 上的 `2p²−8p=2(p−2)²−8` 求下界 −8，并检查 p=2 在域内。
- q30：以 c 为变量、a 为参数，验证 `25c²−10ac+2a²+4/a²=(a−5c)²+a²+4/a²`，输出含参数下界及 c=a/5。是否同时满足 c<b 和其他取等条件，由 M13 联立验证。
- 必须区分已证明的界和在原可行域内可取的最值。其他参数分类、区间端点和不可达界的完整支持范围，在实现契约中明确。

### 2.5 M13：闭合所有条件

极值题联立所有求界环节的取等条件与原可行域，串联换元/消元还原，验证原目标确实达到该界；保留全部合法符号分支。中间式的取等值合法，不代表原目标已经取等。

范围题验证候选集合中的每个值都能还原到原问题；q17、q18 必须提供参数化还原，不能只检查端点。

### 2.6 M14：首轮求解范围

输入已有验证事实中的一个不等式、指定实变量与实数域或一个已验证区间。代码计算结果，LLM 不填写根、符号判断或区间作为事实。

支持有理数系数、次数不超过 2 的单个多项式不等式，比较符为 `<、≤、>、≥`；包含一次/常数退化及非零有理常数分母。记录负数缩放时的方向变化，精确处理判别式、重根、开闭端点及与输入域求交。输出可为区间并、单点、空集或全域，端点使用有理数或精确代数值。

首轮不覆盖参数系数、变量分母、绝对值、指数、根式中的变量、高次式及不等式组。不支持输入应明确失败，不能当成空集，也不能丢失定义域。

## 5. 关键多阶段关系

### 5.1 q17、q18：整个区间可达

q17 对任意 s∈[−2,2]，令 `Δ=(4−s²)/3`，取 `x=(s+√Δ)/2,y=(s−√Δ)/2`。两者为实数，满足 x+y=s、xy=(s²−1)/3，故原条件成立。端点对应 x=y=±1。

q18 对任意 s∈[−1,1]，令 `Δ=(1−s²)/3`，取 `u=(s+√Δ)/2,y=(s−√Δ)/2,x=2u`。串联两层还原得到原条件与目标 x/2+y=s；端点为 (x,y)=(1,1/2) 或 (−1,−1/2)。

q19 由判别式得 s≤−2 或 s≥6，与 s>0 求交后剩 s≥6；此时 p=s+3>0。在 s=6 时 u=v=3，还原 a=3,b=3/2。该题只求最小值，验证下界可取即可。

### 5.2 q20、q29：保持同一个目标

q20 的 M01 式链为：

```text
T = (x+y)/(xy)
  = √((x+y)²/(xy)²)
  = √(((x−y)²+4xy)/(xy)²)
  = √(xy+4/(xy))
```

利用 x,y>0 验证 T>0、分母非零及主值平方根前提。M11 得根内表达式≥4，因此 T≥2；取等 xy=2 与原条件联立得到 x,y=2±√2，互换。

q29 的 M01 合并分式后，保持 `T=(a+1)/(a²−a+1)=1/((a+1)+3/(a+1)−3)`。M11 得分母≥2√3−3，并验证 **2√3−3>0**，才能得到原目标上界；原分母为正不能替代所用下界的正性检查。

### 5.3 q30：带参数配方与共同取等

```text
M01：T = 2a²−10ac+25c²+1/(b(a−b))
M11：b(a−b)≤a²/4，故 T≥B₁=2a²−10ac+25c²+4/a²
M12：B₁=(a−5c)²+a²+4/a²≥B₂=a²+4/a²
M11：B₂≥4
```

第一次 M11 使用 b>0、a−b>0 及和为 a 的关系，取等 b=a−b。M12 输出取等方程 a=5c，不提前宣称对任意给定 a,b 都可在原域取到。第二次 M11 取等 a²=4/a²。

M13 联立得到 a=√2,b=√2/2,c=√2/5，验证 a>b>c>0 并代回目标为 4。全链为 4 种 Method、5 次调用；配方求界不增加额外的等价整理调用。

### 5.4 q31：两次整理作用于不同阶段

第一次 M01 对完整目标验证：

```text
T = (3a/b+1/(ab))/(1+c²)+2c²
  = (3a/b+(a+b)²/(ab))/(1+c²)+2c²
  = (4a/b+b/a+2)/(1+c²)+2c²
```

使用 a+b=1，只改写括号内负二次项；其余部分保持不动。第一次 M11 验证 4a/b 与 b/a 的乘积为 4，以及外层 1/(1+c²)>0，得到：

```text
T≥B₁=6/(1+c²)+2c²，取等 b=2a。
```

第二次 M01 只整理下界对象 B₁，第二次 M11 继续求界：

```text
B₁=2(1+c²)+6/(1+c²)−2≥4√3−2。
```

两正项乘积为 12；取等得 `(1+c²)²=3`，由 1+c²≥1 得 c²=√3−1。M13 联立 b=2a、a+b=1，保留 c 的正负两支并验证原题。全链为 3 种 Method、5 次调用；两次 M01 间存在不等式估计，不能拼成一次纯等价改写。

### 6.1 31 题网页生成目标

本设计的产品验收目标不是只验证若干 Method，而是使 `inequality-basic-q01` 至 `inequality-basic-q31` 全部经过同一条确定性网页生成链：

```text
题意与数学表达式抽取
→ FunctionalPlan / Method 编译
→ Runtime 求解与 Canonical Fact
→ ExplanationSnapshot

→ 基本不等式网页
```
