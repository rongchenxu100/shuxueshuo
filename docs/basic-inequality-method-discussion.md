# 高中基本不等式 Method 逐题讨论表

> 状态：逐题讨论底稿；已确认条目代表设计共识，不代表已经实现或通过端到端测试。最近更新：2026-09-10。
>
> 目的：把候选 Method 与 31 道现有课件题放在同一份表中，后续逐题讨论、合并、拆分或删除 Method。

## 1. 讨论约定

1. 本文只讨论 `Method`，暂不把 `Family`、`Recipe` 和教学步骤混入 Method 数量。
2. `Method` 可以是有固定数学逻辑的 Method，也可以是供 LLM 按 scheme 填写题目特定推导的空 Method。空 Method 不负责寻找推导，只规定数据协议、校验入口和通用展示方式。
3. 有固定数学逻辑的 Method 应由自身的讲解器自动拆分教学步骤；LLM 只提供调用参数，不逐条填写该 Method 内部的展示步骤。
4. 一道题可以调用多个 Method；同一个 Method 也可以在一道题中调用多次。
5. “候选 Method 链”只是当前讨论起点。每讨论完一题，就在“讨论结论”中记录最终拆法。
6. 现有网页解法来自 `internal/senior-high/lesson-specs/inequality-basic-q01` 至 `q31`。

### 1.1 已确认原则：空 Method 与 Method 内部讲解步骤

- “整理目标式”需要一个空 Method：LLM 按统一 scheme 写入题目特定的等价变形过程，代码负责校验并对应通用展示逻辑。
- “构造并确认定和/定积正项”不单独作为 Method。它是“应用二元基本不等式”Method 的内部讲解步骤，由该 Method 根据输入自动拆分出来。
- 因此，Method 数量按可独立调用的能力计算，不按页面上出现了多少个视觉节拍计算。

### 1.2 已确认原则：代码组合学生步骤与前端展示

- Method spec 继续声明自己的讲解内容与展示组件；一个 Method 可以提供多个展示片段。片段不是新 Method，也不是新的 MathObject 或状态版本。
- 讲解层由代码确定性地分组、排序片段，同时组合学生文字步骤和前端展示，避免两者脱节。LLM 不填写学生步骤、组件或播放节拍。
- 学生步骤只组织“标题＋有序片段引用”，不重新声明数学内容或组件；前端用通用容器排列各片段，不重新判断数学。
- 跨 Method 合并须验证目标身份、准确状态版本和实际输入依赖衔接，且不存在必须先讲解的中间变形；不能仅按调用相邻或题号合并。
- 例如 q08 的“整理片段＋M11 结构识别片段”可组成“观察结构”；M11 的应用片段另成“应用基本不等式”。正项与定积事实必须来自 M11 的成功记录，不由 M01 或前端猜测。
- 一个 Method 也可拆为多个学生步骤：q03 的“观察次数”和“配齐次式”必须分开，让学生先理解为什么整理，再看怎样整理。
- 上述片段名称是概念角色，正式字段沿用或扩展现有 spec 机制时再确定；跨 Method 组合与 q03 拆分尚未实现验收。

### 1.3 已确认原则：公共 Plan schema 与 Method 参数分离

公共调用外壳保留 `step_id`、`capability_id`、`args`、可选 `parameters`；具体推导参数由 Method 自己的 `parameters_schema` 严格校验，不把所有 Method 的内部参数枚举进公共 Plan schema。增加 Method 只需注册其契约，不应反复修改公共调用结构。Prompt 中的候选方法协议从注册信息生成；`parameters` 是待验证字面量，不是数学事实。

## 6. q02、q03 已确认的详细设计

本节记录 2026-09-10 的讨论结论，不代表新能力已实现。当前 q08 确定性测试只覆盖整理前缀；尚未验证 q02/q03 完整链路或跨 Method 教学组合。

### 6.1 q02：定和求积，再回接原目标

题目：`x,y>0, 1/x+1/y=1`，求 `xy` 最小值。

Method 链：**M11 → M13**，不调用 M01 或 M10。

| Method | 已验证内容与输出 | 学生展示 |
|---|---|---|
| M11 识别片段 | 正项 `1/x,1/y`；和为 1；积为 `1/(xy)`；原目标 `xy>0`，与该积存在正数倒数关系 | 观察结构：定和求积，先控制倒数积上界 |
| M11 应用片段 | `1/(xy) ≤ ((1/x+1/y)/2)^2 = 1/4`；由正性得到 `xy≥4`；产生取等方程 `1/x=1/y` | 应用基本不等式：公式代入、界的方向转换 |
| M13 | 联立取等方程及原条件，得 `x=y=2`；检查正性并代回 `xy=4` | 验证取等：最小值为 4 |

- `u,v` 若出现在公式模板中只是两个正项的展示角色，不必建立换元 MathObject。
- 现有网页用根式形式推导同样正确；上表采用等价的定和求积形式，便于显示倒数积与原目标的关系。
- M11 只支持经代码验证的有限目标对应：直接和/积、常数平移、正系数缩放、正数倒数关系。不得扩成任意单调变换或通用不等式求解器；不在支持范围时明确报缺口。
- 正项确认和倒数界回接是 M11 内部的验证与展示，不因画面拆分而新增 Method。

### 6.2 q03：观察次数与配齐次式分为两个学生步骤

题目：`x,y>0, 1/x+1/y=1`，求 `x+4y` 最小值。

Method 链：**M01 → M11 → M13**。M05 不单独调用；“配齐次式”是 M01 中经验证后选择的教学模式。

#### M01 的候选推导参数

“观察次数”由代码从已验证推导及所用条件提取：目标 `x+4y` 为 +1 次齐次式，条件左式 `1/x+1/y` 为 −1 次齐次式，两者相乘为 0 次。只有次数关系验证通过，才生成该片段及次数图示；不能仅凭“乘入一个等于 1 的式子”认定配齐次式，也不要求 LLM 填写次数、观察理由或展示标签。数学验证成功但教学分类不足时保留普通推导，不编造观察步骤。

#### M11 与 M13 的职责

- M11 选择整理后目标中的 `x/y`、`4*y/x`，验证二者为正且乘积为 4；常数 5 不参加二元基本不等式。
- M11 应用后得到 `x/y+4*y/x≥4`，依据已验证整理结果回接完整目标 `x+4y≥5+4=9`，并产生取等方程 `x/y=4*y/x`。
- M13 在 `x,y>0` 下由取等方程得 `x=2y`，结合原条件解得 `x=3,y=3/2`，代回目标等于 9，完成可达性验证。
- “两个正项、定积 4”来自 M11，不由 M01 的整理结果或前端自行推断。
