# 错题本内容与页面构建规范

整理日期：2026-09-14。适用于「数学说」错题本的后续选题、讨论、编写与页面修改。

本文件记录讨论中最终确认的做法。后续构建前先阅读本文件；用户对具体题目的新说明优先。当前题目清单和实现入口用于定位，新增内容后同步维护。

## 1. 构建目标

错题本要保留学生当时怎么想，并帮助学生看清：**哪里没有理解、正确思路如何建立、下次遇到同类问题怎样判断。**

题目按知识主题组织，便于回顾课程；同时按错误类型组织，便于把不同题目中的同一个问题放在一起复习。选题和总结围绕可迁移的错误原因，而不是只收集正确答案。

- 优先选择有代表性的概念、推导、分类和边界问题，不必收录所有圈出的题目。
- 单纯计算、代表性不足的题目可以不收录；只需要某一小问时，只保留该小问及必需题干。
- 答案正确但思路不完整，也可以收录。应说明「答案正确，推导中缺少某项判断」，不能写成答错。
- 错误类型依据原解和用户确认判断，不能仅凭题目涉及哪个知识点归类。

## 2. 从原图到网页的工作顺序

1. **确定范围**：记清特训、题号、小问，区分只讨论、已同意加入和已删除的题目。
2. **读取原题和原解**：分别记录印刷题干、学生答案、可辨认的推导，核对符号与端点。
3. **讨论错误原因**：说明原解体现的问题，提出正确步骤的图示结构和可复用总结。
4. **落实用户修正**：原答案、错误原因、教学重点以已确认的信息为准。
5. **加入页面**：用户同意后，完成题卡、分类、共享总结、导航和计数，不重复请求确认。
6. **验证**：先核对数学，再检查两种浏览方式、图形和移动端布局。

讨论阶段不自动把所有题目加入网页。已经授权加入或修改的内容，应直接完成。

### 原图读取约束

- **不能根据笔的颜色推断作者。** 用户曾说明红笔就是荣同学的原步骤，也确认过黑笔才是原答案。
- 涂改或符号模糊时，针对关键内容简短确认；不能把猜测写成事实。
- 只有原答案时，不补造学生的推导过程。可以说明「原图仅记录答案」。
- 特别核对：`< / ≤`、`> / ≥`、`∈ / ⊆`、真包含与包含、交并补、正数与实数、数与有序数对、任意与存在。
- 原解转录和正确解答分开；不要默默把原解中的错误改正确。

## 3. 每道题的固定结构

题干始终可见，题号明确。跨特训引用使用「特训五 · 第15题」这样的完整来源，避免同号题混淆。

| 区域 | 内容 | 默认状态 |
| --- | --- | --- |
| 题干 | 题号、所选小问、必要条件、选项 | 可见 |
| 01 原解题步骤和答案 | 学生实际的判断过程和原答案 | 折叠 |
| 02 正确解题步骤和答案 | 从理解题意到得到结论的推导与图示 | 折叠 |
| 03 错误总结 | 可迁移的结论和判断方法 | 折叠 |

三步均默认折叠，便于浏览题干和自主回想。沿用现有展开／收起交互。

### 01：忠实呈现原解

用学生当时的视角呈现，不提前混入讲评。多选题适合逐项列出「选项、判断过程、判定」，保留漏选、多选等真实结果。

例如学生把集合看成值域，原解可以写：

> 因为 y=x²+1≥1，所以集合为 [1,+∞)，不等于 ℝ。

「把集合元素错看成 y」属于后面的分析，不写成学生当时的思考。删除没有信息增量的重复标题，如表格上方的「荣同学的判断」。用具体数学对象表达，避免只说「左边」「整数之比」而让学生重新寻找所指。

### 02：让正确思路可见

先解释题目真正要求什么，再把条件转成数学关系，最后计算并汇总结论。图中的每个箭头都要表达真实的推导、分类或合并。

- 需要分类：先给分类依据，再分支、分别求解、合并。
- 需要理解题意：先展示自然语言和数学含义的对应关系。
- 原解漏掉的关键检查、漏选或需要纠正的判断，用现有红色样式突出，其余内容保持正常层级。
- 本题的具体数值、数轴、坐标图和反例放在正确步骤中。
- 不用一串装着长段文字的方框代替解释；应画出对象、区域、选择或推导方向。

### 03：总结成可复用的方法

总结采用 **明确的结论 + 如何判断**。标题让学生一看就知道要解决什么问题，正文用必要的图示和短说明解释。

同类题复用同一总结；同一错误类别下有不同方法时，分别保留并标明来源。共享总结使用题目中实际编写的「错误总结」，不要再生成一套简化文案。

「简洁」指删除重复和无关扩展，不是机械压成一句提醒加一行「检查顺序」。此前压缩后的总结已按用户要求恢复；具体删减遵循用户对该区域的意见。

## 4. 两种浏览方式

### 导航与内容复用

- 主题快速定位用「集合概念」「集合间的关系」「并集与交集」「全集与补集」「充分条件与必要条件」，不能只显示「特训一、特训二」。特训编号仍用于标识来源。
- 错误类型使用完整名称，不擅自缩写。
- 快速定位链接**平铺、自动换行，不出现横向滚动条**。
- 保留固定导航，锚点跳转留出导航高度，避免遮住目标标题。
- 添加或删除题目时，同步更新题数、分组、导航和锚点。
- 两种视图共用同一份题目内容，切换时保留展开状态和图示交互状态，不生成重复的页面 ID。
- 相同总结只出现一次。一个类别含不同总结时，用「特训三 · 第12题的错误总结」等来源说明分别展示。

## 6. 各类总结的可视化方式

### 二次项系数

以一般式 ax²+bx+c=0 为中心，框出 a，分成 a=0 与 a≠0 两支。a=0 展示二次项消失、bx+c=0，说明按剩余方程讨论，不使用二次方程判别式；a≠0 区域只保留「是一元二次方程」的判断。

用户已要求删除这段通用总结中的 b=0／b≠0 细分、判别式与根数展开、底部「记住顺序」。后续不要无意恢复。本题所需的根数判断仍可放在正确步骤中。

### 描述法中的集合元素

突出竖线前收集的对象，与竖线后的条件区别开。用同一条件分别收集 x、y、(x,y)，画出对应的数轴范围或平面点集，让学生看到三种集合的差别。

例如用 y=x²：收集 x 得到 ℝ，收集 y 得到 [0,+∞)，收集 (x,y) 得到抛物线上的点。条件中出现某个变量，不意味着集合就在收集该变量。

### 分类列举不遗漏

保留两种方法图，不强行合成同一段提醒：

- **交集个数求参数**：将有序元素放在数轴上，列全满足数量要求的候选组合，排除不可能组合，再分别写端点条件并合并范围。区间包含两个点时，不能跳过夹在它们之间的点。
- **带条件的子集计数**：将元素分为受限制的一组和自由选择的一组，用选择树或组合表列全。一组至少选一个、另一组可以不选时，「不选」也必须画成明确分支。每个最终组合对应唯一集合，既不漏也不重复。

### 边界代入验证

用数轴对齐两个集合的端点，明确空心／实心点，展示「代入边界参数 → 得到两个集合 → 检查原关系 → 是否允许取等」。

开区间只说明元素端点不属于集合，不能据此把参数条件都写成严格不等式。端点位置相同，包含关系仍可能成立。若要求真包含，在保证包含后，再检查两个集合是否相等；至少一侧严格即可。

### 集合关系与维恩图

画出全集 U、集合及有关区域：交集突出重叠、并集突出合并、补集突出全集内的外部、包含关系突出内外集合。

复合运算拆开画中间对象，再画运算结果。例如先分别标出 ∁ᵤA、∁ᵤB，再取交集，不能只给最终图后用一句话解释。

图必须满足题设；要求某区域为空时，明确标记无元素。判断普遍命题不能凭一幅随手画的图断言成立；否定时可构造一个符合前提的反例。

### “任意”与反例

画出对象及检查结果，分成「全部满足」和「出现一个不满足」两支。证明成立需覆盖全部，否定只需一个反例。有限示例只是示意，不能把几个勾号当成无限对象全部成立的证明。

特训一第15题的流程：理解“任意” → 分别写出好集、坏集的判断要求 → 两支分别解 A、B → 汇总结论。明确「至少一个成立」的否定是「两个都不成立」。

### 包含关系中的空集

从 B⊆A 出发，先分 B=∅ 与 B≠∅：空集分支说明 ∅⊆A，并计入对应参数；非空分支再比较元素范围。最后合并两部分参数范围。

### 重复元素只算一次

用合并过程表现：两个相同的根 r、r 收集成一个元素 r；两个集合共有的元素合并后也只留一次。先找出参数导致元素重合的情况，再去重、计数或求和。

### 充分、必要条件的四种关系

沿用题库已有的 p／q 双箭头样式：p 固定在左，q 固定在右。顶部 p→q 判断 p 是否为 q 的充分条件；底部 q→p 判断 p 是否为 q 的必要条件。勾／叉标出方向是否成立。

设 P、Q 分别为满足 p、q 的对象组成的集合：

| p→q | q→p | p 是 q 的什么条件 | 集合关系 |
| --- | --- | --- | --- |
| 成立 | 成立 | 充要条件 | P=Q |
| 成立 | 不成立 | 充分不必要条件 | P⊊Q |
| 不成立 | 成立 | 必要不充分条件 | Q⊊P |
| 不成立 | 不成立 | 既不充分也不必要条件 | P⊈Q 且 Q⊈P |

仅说「充分」或「必要」允许两者同时成立；出现「不必要／不充分」才需排除相等。互不包含不等于互不相交。命题 p、q 与集合 P、Q 不混用。

### 理解题意后确定推导方向

把「题目要什么」与「条件表示什么」分开呈现，再画出两者如何合成求解任务。可用切换示例降低同时阅读的信息量：

- **求一个充分条件**：所选参数范围 H 包含于使命题成立的全部参数范围 A；同时表现命题要求给定范围内的所有对象满足条件。
- **判断两种条件的关系**：把图象位置等描述翻译成参数区域，再比较区域和双向箭头。
- **问参数是否存在**：先翻译成正确的包含方向，再展示固定集合与随参数变化的集合，判断能否满足包含。

特训五第11、13、14题共用这一类总结。共同点是理解任务和翻译条件，不能分别只概括成算范围、看图象或解不等式。

## 7. 图形与文案的共同规范

- 优先复用现有 HTML／CSS／SVG 数学图形，保持线框、箭头、青绿色与红色纠错提示的一致风格。
- 通用总结用字母或明确标注的示例；本题数值放在正确步骤中。示例图标明对应的取值。
- 函数图的原点、坐标轴、根和标签位置符合数学含义；维恩图作为示意图，不冒充坐标图。
- 无界区间用箭头表达延伸；开闭端点用空心／实心点，配合文字或公式。
- 颜色辅助理解，含义同时通过标签、符号、线型或文字表达。
- 公式和标签不挤压、不溢出；并排卡片在窄屏下改为纵向排列。
- 交互用于观察关系变化或分步理解，不为装饰增加操作。只有实际可操作并经过检查的内容才称为交互。
- 少用重复的「检查顺序」「记住顺序」；图已表达清楚的流程，不再逐字复述。

## 8. 已确认、容易被改错的具体约束

- 特训五13、14：先翻译条件及题目要求，再判断推导方向，不跳过理解过程。

### 特训五15：包含、真包含与分类

本题 p 为 x<1−a 或 x>1+a，q 为 x<1/2 或 x>1，两侧均为开端点。p 是 q 的充分不必要条件，要求 P⊊Q。

先保证包含：1−a≤1/2，1+a≥1。再保证不是相等，即至少一侧严格。按用户最后要求，题目正确步骤中的两种情况写为：

1. 左端允许重合，右端不重合：1−a≤1/2，1+a>1，得到 a≥1/2。
2. 左端不重合，右端允许重合：1−a<1/2，1+a≥1，得到 a>1/2。

合并得 a≥1/2，最小正整数为1。这两种情况可以重叠，合并范围即可；不能为了分类互斥，擅自将第一种的 ≤ 改回 =。第一张端点重合图标注「边界示例：a=1/2」，不能让它代表第一种的全部取值。

两个端点同时重合分别要求 a=1/2 和 a=0，不能同时成立。学生原答案1正确；需要补足真包含的验证，不能声称最终范围错误。这一具体分类修正不要求改写其他题目中数学上成立的分类方式。

## 11. 完成前检查

- [ ] 特训、题号、小问正确；没有加入未选题或恢复已删除题。
- [ ] 原答案和原步骤忠实；用户确认已落实；未编造学生思考。
- [ ] 错误归因与证据一致；答案正确但过程不足的情况表述准确。
- [ ] 正确步骤先理解再推导，分类完整，合并范围正确。
- [ ] 充分／必要方向、真包含、空集、边界与去重按本题需要核对。
- [ ] 图形、标签、端点与公式一致；示例没有冒充一般证明。
- [ ] 三步默认折叠；展开／收起、图示交互工作正常。
- [ ] 两种浏览方式内容一致；共享总结正确去重，不同总结保留来源。
- [ ] 标签使用完整名称，快速定位平铺换行；题数与分组更新。
- [ ] 直接锚点、刷新和视图切换有效；固定导航不遮住目标。
- [ ] 桌面约1183px和手机约390px宽度可读，无横向溢出或图文遮挡。
