## 实现

- 新题图片、人工金标、文字辅助及哈希：`server/tests/solver/fixtures/understanding-v2/function-quantifiers/`。新题的文字辅助明确为人工转录，不冒充真实 OCR。原五题使用仓库匹配图片与录制 Paddle 观察，并经过真实观察适配器；k 倍四边形沿用原图和观察夹具。
- 增加通用 `quantified_relation`：forall/exists、实数或区间定义域、局部变量及比较算式。`find_range` 保存所求参数与答案所用参数。保留量词、边界开闭和比较方向，不计算答案。
- 量词变量由代码局部绑定，允许名称变化；代数使用原受控解析器。测试拦截量词互换、开闭端点变化、漏条件、所求参数变化、局部变量逃逸及非法表达式。
- 泛化单题 smoke 的 case 绑定与 matched/unmatched 判定；七题均比较实际题型和金标，而非一律要求 unmatched。图片按实际 PNG/JPEG 类型传输，原图字节及哈希不变。
- 新批次入口 `problem_understanding.batch_smoke` 在任何付费调用前检查全部七题材料、金标及请求。每题独立 Provider 和输出目录，共用代码和验收；目录与语义调用预留防止误恢复重复付费。
- 操作说明来自统一 schema 目录。系统提示与现有 few-shot 未加入本题样本；辅助来源新增显式标记。authoring 版本 v10，模型 schema 17,011 字符；新题完整提示词文本 23,666 字符（不含图片 base64），见 `measurements.json`。

### 新题的具体表现

实际返回正确保留了原文、f/g 两个函数、forall 实数域、exists 闭区间 [1,3]、>=/<= 方向、b²+c² 最小值及 b 的含 c 范围目标，并明确 unmatched，没有补造图形。输出采用 `f(x)-g(x)` 这一自然写法；新增操作说明要求代入函数表达式，但模型未展开。

因此，不能把该失败解释成“模型没有识别任意/存在”。代码目前需要输入端声明 x/y，并要求将函数调用展开为多项式；这两项属于作者接口和转换器的能力边界。本次没有在观察结果后临时改变该边界或重跑改判。后续可以优先补充受控的已定义函数引用展开及函数自变量局部绑定，减少模型的记账负担；仍须保持未知函数、自由变量及作用域错误的拦截。
