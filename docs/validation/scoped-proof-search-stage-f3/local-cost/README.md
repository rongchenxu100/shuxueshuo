# 删除本地热路径中的重复工作

日期：2026-09-28。输入是 F3 `live-02/planner-01` 的两份原始模型响应；不改数学推导，不调用 LLM，不使用题号特判。

## 删除的工作

1. `method_search_service` 删除逐条事实遍历所有生产记录并反复计算整份记录 SHA 的循环。每次 Method 调用从已验证的提交记录建立一次 `proof_ref → record` 索引，再查找事实指向的证书根。复杂度由事实数乘记录体积变为记录体积加事实查找；Scope、有效性、生产记录哈希匹配、节点位置及 checker 重放保留。索引仅限此次调用，不是跨调用授权缓存。
2. `DebugArtifactJournal` 删除 `_matches_snapshot`、`_json_snapshot`、`_json_leaf` 和完整载荷比较缓存。每次发布使用原生 JSON 编码一次，再以编码字节的 SHA 复用版本文件；内存只保留小型文件引用。dataclass/custom Mapping 等非原生对象由 encoder 的 default 按需转换，不预先递归复制整棵载荷。
3. 两种产物模式都删除 JSON 缩进格式化。full_diagnostic 仍包含全部旧视图，compact_audit 仍只省略旧视图，canonical 审计角色都保留。新产物字节和产物 SHA 因去掉空白而变化；证明证书、规则 hash 和 checkpoint 数学内容未改写。原始响应文本不变。字典键使用原生 JSON 编码语义，结构化证据的键均为字符串。

这是对 F2 “先比较快照以减少序列化次数”实现的修订：序列化次数现在等于发布次数，不再把减少次数作为指标；减少的是 Python 递归遍历、载荷缓存、格式化及重复写盘。嵌套变更、变回旧内容、跨角色共享、发布失败、版本只读、平台引用与历史保留仍受测试保护。`conversions` 为兼容旧计数消费者保留，当前为 0（指完整预转换次数，不是 default 回调次数）。

## 证据引用与恢复载荷复用（2026-09-29）

这轮修改限于执行证据、checkpoint 与调试/验收导出，没有调整数学搜索、checker 或证明额度。

- 新辅助执行证据使用 `scoped-proof-commit-ref/v1`，携带 source、call/commit 身份和依赖边；完整证明记录由恢复状态内的事实库保存。旧 `scoped-proof-commit/v1` 仍可读取。外部 checkpoint 读取核对引用与恢复事实库中的身份、依赖、proof_reads，再核对 checkpoint 内容签名；真正恢复事实库仍独立回放。
- 恢复状态先持有脱离输入的递归不可变数据，再生成一次规范 JSON；后续 authority 导出从保存文本生成独立字典，不再反复进行 Python 层规范化和排序。修改输入或导出字典不会污染恢复载荷/签名。该复用仅属于对象自身，不跨求解或信任域缓存。
- 调试 transaction 的完整事实库和逐调用 proof_commit 改为引用同阶段不可变 checkpoint 版本，引用含文件 SHA、JSON pointer 和 commit 身份。无 checkpoint 的失败阶段仍保存内嵌证据。证据 index 标记 `proof_storage: checkpoint-references/v1`；文件仍以 `.json` 结尾，现有评审监视器会收集。普通 Runtime `to_payload()` 不传调试引用参数时保持完整输出。
- authoring 工具的 `result.json` 改为 `solver-authoring-summary/v1`：答案、检查、错误、统计、推导摘要及每次尝试的不可变 index/history 引用。仅精简验收落盘文件，返回的 SolverResult 和产品 API 不变。没有证据 index 时保留完整导出。
