## 南开：题型机制推敲仍然占用大量思考

本次新 thinking 共 311 行。有效来源核对包括第四象限的两个严格不等式、E/G 分别所在的线段、F 中点、DE=√2·NG、两小问条件隔离，以及“此时”修饰方程和 G 坐标两个目标（L22–30、52–54、159–165）。这些需要对应原图，不是单纯 JSON 校验。

问题集中在：

1. **反复分析如何解题。** L34、82、193、273–275 多次讨论 DE=√2·NG 是否意味着加权变换。L193 长篇猜测路径转化，还讨论“胡不归”“阿氏圆”；最终仍以目标 EG+FG 不含权重、没有射线和正方形接受原 family。注册表的“路径机制本身是否依赖……”让“不求解”与“检查题型适用”之间产生张力。
2. **再次纠结可选声明。** L22、36、127、149、209、231 多次怀疑没有 E/G 动点标签是否遗漏；候选已有取值线段、约束和最值目标，当前契约允许省略标签。L253 还检查 ∧ 能否写在 JSON 里，这属于代码已检查的内容。
3. **来源可辨认性没有得到新的可靠验证。** L7、68、115、185 直接把 DM 与 DN 的关系读为等号，没有输出 uncertain。未再出现早期日志中“因为题目需要所以接受”的显式理由，但也没有新的可辨认证据；原始扫描的符号风险 [MN-003](../../math-notation-known-issues.md#mn-003原图复核用题型常识消除了持续的视觉疑问) 继续开放。这里不判定 DM=DN 关系错误。

最终 thinking 仅降 1.88%，耗时反增。这次不能认为南开复核效率已改善。

## 河西：最明确的干扰来自旧字段要求

本次新 thinking 共 291 行。有效检查包括 -b*x 的负号、b+1/2 的分数范围、∠CAD 的顶点、N 的正半轴、各小问独立的 a 值与 A∈Γ（L24、41–50、79、101）。

但请求的 `registered_families` 仍含：

> 必须用 path_minimum_target 声明完整带权路径；sibling 比例事实不可替代。

这是沿用旧类型事实的编写指令。当前候选已改成数学字符串，`min(sqrt(2)*MN+AN)=21/4` 已表达完整条件；review Prompt 虽然说明 primitive 分类名不是候选必填字段，但两处要求相互干扰。新 thinking 的 L57、119、156、188 多次怀疑候选缺少 `path_minimum_target`，该名称全文出现 **13 次**。

还有两个清晰现象：

- L125、152、170 开始把 A 的坐标代入曲线，推导 c 或 y_M，随后又承认抽取无需展开。这些推演没有发现来源差异。
- L252 已表示可以 confirmed，后面仍反复核对到 L291；全文 confirmed 出现 **14 次**，包含讨论输出格式的出现，不代表 14 次独立判断。L228/L270 又检查 confirmed 是否要求 findings 为空，完整 Schema 并未阻止这类重复。

这比简单加一句“不要重复”更可操作：应清理实际进入 review 的题型目录，而不是继续补一句解释旧字段不用输出。本轮未修改该目录或 Prompt。

## 西青：明显缩短，但仍反复讨论 at

本次 thinking 共 116 行，核对了 -x²、m>0、D 的坐标和曲线归属、AD=2BC、5+5√3，以及 b=4 仅属于第(1)问（L18–26、38、66、68、108）。

L28、60–64、88、94、112–114 多次回到同一个问题：求 b 时，额外的 `at: 2DM+AM=min(2DM+AM)` 是否属于新增条件。候选 facts 已完整保留最小值条件，最终接受与之前修正后的代码判断一致，没有误改题目。

可见的诱因是 `candidate_contract.goal_fields.at` 沿用了“仅在题面明确……时填写”的**抽取编写规则**，而 review 又要求不能仅因多写/少写 at 判错，要检查是否改变所求。模型反复在“如何写更合适”和“已有表达是否改变题意”之间切换。

本次思考使用英文，不能把中文关键词出现次数减少当成改进证据；表中使用供应商报告的 reasoning token。thinking 降 58.18%、总 token 降 19.41%，是本轮成本改善明显的一题，但仍保留重复现象。

## 下一步建议（本轮未实施）

1. **首先清理 review 所见的题型目录。** 输出以题面为依据的简洁判据：所求/已知最值的路径是否有非 1 权重、是否明确出现射线/正方形及其关系。移除旧 fact JSON 字段要求与“需要何种求解变换”的内部指令。保留类型 ID 和来源排除条件，不把 match 声明合法误称为语义已证明。
2. **将复核接受规则与抽取编写偏好区分。** candidate_contract 说明字段含义，不要求 review 重新选择更漂亮的记法。对 at 等冗余，只提供代码确实已证明且绑定当前候选/路径的等价结论；未经证明的状态变化不能一概放过，也不能引入金标或答案。
3. **后续用真实对照评价 thinking 模式。** 现有 low 已出现长循环；继续叠加“不要重复”的文字并未稳定解决。若比较关闭 thinking 或更紧的 review 策略，应同时测试正确、单点错误、模糊图片候选的误报、漏检和不确定处理，不能仅以本轮三个 confirmed 作为依据。未自动发起这些额外调用，也未降低 token 上限来截断 JSON。

以上建议来自日志中的具体行为，不把一次模型自述当成可靠图像证据。三题输入原本均已被现有金标接受，本轮无法衡量 review 对真实错误的检出能力。历史记录、冻结成绩及旧候选均未改写。
