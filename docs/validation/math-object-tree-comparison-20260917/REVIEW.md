## 几何和代数差异的人工解释

**和平二模的中心。** 正方形 `AEKG` 的对角线为 `AK`、`EG`，它们互相平分。因此交点 `H` 同时为两条对角线的中点。这里的不同写法可以解释为等价表示；若后续将它自动消差，需要记录所用的正方形条件和定理，不能无条件把一般四边形的交点改成中点。

**和平一模的两个横轴交点。** 由 `A=(-1,0)` 在 `y=ax²+bx−3` 上，得到 `b=a−3`，因而

```text
ax²+bx−3 = (x+1)(ax−3)
两根为 -1、3/a；a>0，所以两根不同。
```

在新输入的“全部横轴交点为 `{A,B}`”语义下，可以推出 `A≠B`。当前比较器未完成这段推导，报告继续显示事实差异。

**西青一模的两个横轴交点。** 由 `A=(-1,0)` 在 `y=−x²+bx+c` 上，得到 `c=b+1`，因而

```text
−x²+bx+c = −(x+1)(x−b−1)
两根为 -1、b+1；b>0，所以两根不同。
```

同样可以结合完整交点集合推出 `A≠B`。这是一条有前提的等价解释，不是“不同字母总代表不同点”的规则。

## 对后续规划最重要的发现

`min_{n}(f(n,b))=k` 与一个不记录最值变量的 `min(f)=k` 在数据契约上不能直接等同。规划需要知道谁在变化、谁是固定但待求的参数，以及最小化时必须满足哪些条件。部分现有规范化会忽略最值变量；本次审计额外检查这些字段，并用改变量的反例验证不会误报一致。

“最小值等于某数”与“求达到最小值时的点坐标”也要分开保留。南开Ⅱ②和和平二模Ⅱ的 `at` 是下一阶段数学视图必须展示的内容。旧题干包含相应语义，旧目标结构没有显式携带，说明不能只以旧结构逐字一致作为正确性标准。

西青的 `vertex(Γ)` 则说明 LLM 不必为了迎合代码而给每个派生对象另造名字。后续编译器可以按需要物化对象，但应保持同一身份、作用域和来源。

## 复现与验证

在 `server` 目录运行，输出目录必须是尚不存在的目录：

```bash
PYTHONDONTWRITEBYTECODE=1 PYTHONPATH=. .venv/bin/python tools/compare_problem_math_trees.py --output ../docs/validation/math-object-tree-comparison-new-run
PYTHONDONTWRITEBYTECODE=1 PYTHONPATH=. .venv/bin/python -m pytest -q tests/solver/test_math_tree_audit.py
```

真实候选可通过 `--notation-dir DIR` 输入，文件名沿用题目 ID；使用 `--case` 可选单题。默认退出码 0 仅表示审计运行完成；加 `--require-equivalent` 才会对未解决差异返回非零状态。
