仍有两个反复点：

1. **O 是否默认原点。** L17、43、69、71、83、101 再三讨论同一问题，“原点”仍出现 16 次。设计文档已明确本题采用原点惯例，但通用记法目录没有给出这一规则。后续可把适用前提明确写进通用约定：坐标题的原点惯例不得覆盖题面另行定义的 O，也不能把任意名为 O 的点自动当原点。
2. **已经确认后重新检查连接声明。** L32 已接受由 `segment(B,C)` 覆盖连接 BC，L51、53、81 又回头确认。L79 已认为全部一致，后面仍继续推敲。

所以这次是明显缩短，不能称为已经实现“一次检查后结束”。日志还在 L63 顺带推出 C 的坐标，这对来源核对并非必要。

## 对下一步修改的判断

先补 O 原点等已经定案、但尚未进入通用契约的明确约定，给出适用边界；不再把同类题的具体内容继续堆进 few-shot。原图来源规则和 Schema 规则也应继续分工，复核不能把编译合法当成来源正确。

南开的重复表明，仅扩写 Prompt 不能保证缩短 thinking。若后续调整思考模式或预算，应另做受控实验，并同时测错误检出与误报，不能用截断导致缺 JSON 的方式换取短耗时。本次没有修改模型配置或发起额外调用。

两份候选原本都通过当前金标语义检查，两次 confirmed 只能说明它接受了两个正确候选，**不能证明 review 能发现错题意**。下一次评价应加入同一原图配单处错误候选（如射线反向、删除范围或目标）及真实模糊图对照；把检出率、不确定性处理、重复思考和 token 一起衡量。
