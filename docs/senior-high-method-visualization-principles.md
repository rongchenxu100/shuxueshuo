## 1. 整体 Review（基本不等式 · 方法层）

### 1.1 已改版、结构统一（6 张方法卡）

| 方法 | 核心图像 | HOW 管道第三步 | 路径数 | 状态 |
|------|----------|----------------|--------|------|
| 直接应用基本不等式 | 四类正项 + 空方框公式 | 验证取等 | 2 | ✅ 成熟；核心区多一段说明文字，可再收 |
| 配齐次式 | m/n/0 次方框 + 比值 pill | 检查乘积定值 | 2 | ✅ 成熟；核心仍带示例式子（x+y 等），属「半抽象」 |
| 找对称结构 | x↔y 交换流 + s,p pill | 验证取等 | 2 | ✅ 成熟 |
| 多次应用基本不等式 | n−k 公式 + 预计次数 | 验证取等 | 2 | ✅ 成熟 |
| 换元法 | 分母/根号触发 + u=□ | 验证取等 | 2 | ✅ 成熟；换元为改写手段，换元后再观察结构 |
| 条件消元法 | y=□ → 目标整式→一元式 | 验证取等 | 2 | ✅ 成熟 |

**共同优点**

- 「核心意义 / HOW」两层分工清晰：核心只建图像，HOW 承担步骤与例题。
- 管道三步 + 双路径例题已成为可识别的家族语言。
- 底部 pill（`X ⇔ Y`）一句话收束方法本质。
- 例题步骤复用 `basic-slot-route-*`，信息密度可控。

### 1.2 不同范式、暂不要求统一（2 张）

| 卡片 | 范式 | 说明 |
|------|------|------|
| 两个正数的基本不等式（定理） | 证明表 + 等价形式轨 | 性质/定理卡，不是「解题方法」；保持多证明并列 |
| 一正、二定、三相等 | CHECK FLOW 三连检查 | 判断链，不是 CORE/HOW；「三相等」即取等验证的另一种说法 |

### 1.3 优化记录（2026-03-02 已完成 P1–P3）

- **P1**：直接应用核心区说明移至 HOW ①；多次应用删除重复副标题；配齐次式保留 `x+y` 等示例。
- **P0/P1 术语**：对称结构、换元法管道用语统一为「条件整式 / 目标整式」。
- **P2**：引入共享类 `method-intro` / `method-core` / `method-how`；删除 `fixedProduct*` 渲染器与旧版 CSS。
- **P3**：对称结构、条件消元法路径补充「同类」脚注。

### 1.4 后续可选

- 配齐次式 HOW 管道可进一步对齐 `basic-slot-pipeline` 类名（当前为 `homogeneous-route-pipeline`）。
- 换元法第二条路径若无同型练习，可不强制脚注。

## 2. 方法卡可视化规范

### 2.1 一张方法卡固定三块

```text
┌─ 核心意义（header）────────────────────────────┐
│  [核心意义] 一句话：这个方法在做什么              │
├─ 核心图像（core-template）─────────────────────┤
│  只建抽象操作图像；空方框 / 结构符号 / 公式关系   │
│  底部 pill：X ⇔ Y                              │
├─ HOW（method-how）─────────────────────────────┤
│  [HOW] 先…，再…（副标题）                       │
│  管道 ① → ② → ③                                │
│  （可选）轻量示意图；能省则省，例题里体现即可      │
│  双路径例题卡 × 2                               │
└────────────────────────────────────────────────┘
```

**禁止放在核心区的内容**

- 完整题面、多步推导、「注意」「一句话」式重复总结。
- 与底部 pill 重复的标签（同一概念出现三次以上）。
- 仅为装饰的循环箭头、过大字号公式（`令 u =` 等应紧凑）。

**允许放在核心区的内容**

- 结构符号：分数线、根号、方框、交换箭头、次数上标。
- 极简占位：空方框、虚线框、`…` 表示「此处为整式」。
- 一个核心公式或计数关系（如 `n−k`、`m+n=0`）。

### 2.2 核心图像设计原则

| 原则 | 说明 | 示例 |
|------|------|------|
| **结构先于实例** | 核心回答「看到什么结构」，不绑定某道题的字母 | 换元：`1/[□]`、`√[□]`，而非 `x+1` |
| **半抽象例外** | 配齐次式可在核心保留示例式子，帮助理解次数关系 | 核心展示 `x+y` 与 `1/x+1/y`，并标注 m、n、0 次 |
| **空方框语义一致** | 方框 = 「待填入的完整结构」或「待表示的式子」 | 正项槽位、分母、根号整体、`y=` 右侧 |
| **触发类型要可数** | 学生应能归纳「几类入口」 | 换元两类：完整分母 / 根号整体 |
| **单轴流向** | 优先 ↓ 或 → 一种主方向；避免 V 形双箭头汇聚 | 换元：横排「或」优于 ↘↙ |
| **pill 收束一句** | `A ⇔ B`，A 为方法名或触发，B 为结果或操作 | `消元 ⇔ 目标整式降成一元式` |

### 2.3 HOW 区设计原则

| 要素 | 规范 |
|------|------|
| **管道** | 固定三步；编号 ①②③；每步有 **名称 + 小字** |
| **第三步** | 统一 **验证取等**（与「一正二定三相等」中的三相等同族） |
| **路径** | 默认 2 条：「直接 / 整理后」或「类型 A / 类型 B」 |
| **例题** | 每路径：题面 → 2–4 个命名步骤 → `验证取等` 结果行 |
| **步骤标签** | 用动词短语：整理条件整式、表示代入、乘入定和配齐次… |
| **示意图** | 非必要不放在 HOW；同步改写类逻辑由管道 + 例题承担 |

### 2.4 术语表（方法层统一用词）

| 推荐 | 避免混用 |
|------|----------|
| 条件整式 | 条件、条件式 |
| 目标整式 | 目标、目标式、目标表达式 |
| 验证取等 | 联立取等、还原取等（可作小字说明） |
| 完整分母 / 根号整体 | 复杂分母、根号下式子（除非在例题里） |
| 一元式 | 一元目标、单变量式（核心 chip 可用「一元式」） |

**换元 vs 消元**

- 换元：引入新字母 `u`，改写条件整式与目标整式。
- 消元：不引入新字母，由条件整式表出一个变量后代入目标整式。

### 2.5 视觉样式约定

- **核心意义 / HOW 标题**：左侧 pill 标签（核心意义 / HOW）+ 右侧一句副标题；背景浅渐变，与方法卡顶栏区分。
- **路径卡片**：`basic-slot-route-card`，`is-direct` / `is-rearranged` 顶色区分。
- **颜色语义**（基本不等式章节已用，可延续）  
  - 青蓝：和/条件/分母侧  
  - 橙：待替换变量、根号侧、强调项  
  - 绿：结果、取等、一元式侧  
- **字号**：核心公式小于早期版本；核心区纵向紧凑，目标高度约 200–280px（桌面）。

### 2.6 何时不用本规范

| 场景 | 改用 |
|------|------|
| 定理证明、等价形式罗列 | 证明表 / FORM MAP（如基本不等式定理卡） |
| 使用条件检查链 | CHECK FLOW（如一正二定三相等） |
| 穿针引线、数轴、符号图 | 表格/数轴组件（不等式基础章节） |
| 课时页逐步讲解 | `visual.kind` + lesson spec（见 inequality skill 文档） |

### 2.7 方法索引判题路由（基本不等式）

拿到题后，在「一正」之后按两层判断；**换元不是与对称、齐次并列的第一入口**，而是结构被挡住时的改写步骤。

```text
第 1 步：观察条件整式 │ 目标整式（结构扫描，并列）
  ├─ 能看到定和或定积（整理后露出两个正项）→ 直接应用
  ├─ 交换变量后二者都不变              → 对称结构
  ├─ 次数可配成 0（一正一负或局部不齐）  → 配齐次式
  └─ 多变量、且预判需多轮配对消元        → 多次应用

第 2 步：分母/根式挡住结构？
  └─ 令 u 等于完整分母或根号整体，同步改写条件整式与目标整式
     → 回到第 1 步继续观察

兜底：上面都不顺，但条件能表出一个变量 → 条件消元法
```

**换元法文案禁忌**：不说「同一整体反复出现」；应写「完整分母 / 根号整体」「换元后再观察定和、对称或齐次」。

**方法索引可视化**：与方法卡同族——`method-intro`（核心意义）+ `method-core`（结构图）。核心一句：**选方法的关键，是先观察结构**；核心区为「条件整式 — 观察结构 — 目标整式」焦点图 + 四条线索 tile（定和/对称/齐次/多轮，可点击）；底部 pill「观察结构 ⇔ …决定第一入口」；下方两卡为换元改写与消元兜底；最后「落地：验证取等」。省略「一正」前提；不再另设方法卡片网格。

## 3. 新建方法卡检查清单

在 `senior-high-library.js` 增加 `render*Visual` 前，逐项确认：

- [ ] `learning-topics.json` 中 `groupId`、例题分组、`body` 与可视化分工不重复
- [ ] 核心意义一句话能脱离例题单独读懂
- [ ] 核心图无具体题面字母（或明确标注为「半抽象」例外）
- [ ] 有且仅有一个底部 pill
- [ ] HOW 管道三步，第三步为「验证取等」
- [ ] 两条路径覆盖主要分叉，脚注「同类」
- [ ] 例题步骤无临时辅助元（除非方法定义需要）
- [ ] `tools/tests/senior-high-library.test.mjs` 断言核心/HOW 关键字符串与负向断言（核心不含例题锚点）
- [ ] 移动端：管道竖排、路径单列、核心箭头旋转 90°（复用现有 `@media` 模式）
