# 逐帧数学状态机制（v1）

绘图必须读取当前教学步骤、当前分支可见的数学状态。几何注册表只是对象目录，不能把整个目录当作当前场景，也不能把后续答案提前带入前面的步骤。

## 数据流

`Verified TeachingSource → BranchVisualState → FrameMathStateResolver → VisualFrame → validator → compiler`

- `parameter_identity.py` 统一读取已验证的 ParameterValue、闭合 Coefficients 和 parameter_solution。零是有效值；含自由符号的系数关系不能冒充已求出的参数。
- `recursive_state.py` 随分支克隆参数、可见对象和数学约束。子分支状态不回流到父级或兄弟分支。
- `math_state.py` 在当前帧已经可见的对象集合内选择版本。曲线使用 objectRef 标识数学对象，scopeId 和 stateRevision 决定有效版本；不同对象即使方程相同也不能合并。
- 曲线闭合时，规范名称可以对应原题的 function handle。输出改名的情况，需要生产者读取唯一规范曲线，并且其输入曲线代入已验证参数后与输出符号等价，才能继承身份；无法证明时保留独立结果身份。
- 点优先使用 sourceRef；只有在作用域内身份唯一时才允许规范点名回退。匿名 StepResult 和候选点不按坐标或字母合并。
- 替换对象时同步更新依赖对象和动画引用，丢弃旧坐标注记，之后才生成参数契约和视口。

## 保存关系，而不是保存上一次坐标

探索步骤可以保留滑块；取等结果需要保留取得等号的数学关系。适配器从已验证角色和符号坐标发布 attainment_constraint，包括参数、方程、合法域、对象引用和来源步骤。

当前接入的关系是路径最值中的共线且在线段内，附带动点载体和等长联动约束。每帧重新代入当前参数求解；探索状态保留自由控制，后续计算状态冻结到精确解。比如本次运行从演示参数改为 a=3/4 后，重新解出 u=5/9，而不是沿用上一帧约 0.699333。

没有唯一合法解、存在未解析符号或几何校验失败时应报错，不能用示意坐标伪装取等结果。状态审计保存在 frame.metadata.mathematical_state，包含版本、作用域、来源、参数、替换记录和约束求解记录。

## 独立校验与扩展边界

校验器不相信审计中的 residual=0，而是使用最终参数和 parameterized_points 重新计算实际坐标，检查共线、点在线段内、载体与等长条件，并检查同一数学对象是否残留两条曲线。

新增几何关系应增加明确的约束类型、由验证来源发布的适配器，以及独立几何校验；不增加题号、特定答案或页面步骤序号分支。v1 不宣称支持任意约束系统、多解择支或所有几何对象的版本化；这些需要明确协议后扩展。

回归覆盖不同参数名称和取值、父子与兄弟作用域、不可见未来版本、同域独立对象、匿名点、参数零值、歧义失败、伪造审计残差，以及录制的真实运行。旧运行证据保持不变；通过离线重放重新生成页面验证。

本机制负责图形状态一致性，不承担自然语言推导的代数等价检查。课程文字中的算术错误需要在 LessonIR 质量校验层处理。

### 具名取等结果与匿名点注册

几何注册与输入角色绑定共用 `_public_point_semantic_ref`。除显式输出目标与答案目标外，单个 Point 返回可由同一 Verified TeachingSource 的 `attainment.points` 唯一角色证据恢复具名身份；坐标只校验这份角色证据，不用于在整张图里寻找重合点。多个 Point 返回或多个重合角色不能据此猜测身份。没有具名证据的 exact result 继续使用 producer/return 独立注册，保持作用域隔离。
