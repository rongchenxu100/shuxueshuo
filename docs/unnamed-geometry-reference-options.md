# 未命名几何对象：已采用的直接关系与备选

2026-09-15。问题：模型不应为了描述题内定义，先决定新增点叫P、X还是O。内部计算需要表示对象，但不要求模型取名。v8 已实现下面的 cut_ratio 直接关系；构造式点引用仍只是备选。

## 推荐：常见关系直接描述，无需模型创建交点

当前已支持 `diagonal_bisects(polygon=ABCD, bisector=BD, bisected=AC)`，模型可以直接写“BD平分AC”，不必先命名交点再写中点。

长度比例已加入通用关系：

```json
{"kind":"cut_ratio","segment":"BD","by":"AC","ratio":["k","1"]}
```

精确定义为：取BD与AC所在直线的唯一交点，以B到交点、D到交点的无向距离按顺序比较，比例为k:1。不自动声称交点在线段内部，不断言它不同于任何已命名点。反向比例必须保留，例如ratio=[1,k]。已知平行、重合或零距离拒绝；未独立证明的存在性写入内部构造审计，不声称已证明可求解。

代码负责内部交点标识、规范化和有依据的身份确认。若题干已写O是AC与BD交点，则引用O；如果仅能依据共线关系证明是O，须经过代码规则确认。多个身份候选不确定时不随意合并。

这是通用截线距离关系，不是k倍四边形类型；也可用于三角形、梯形或任意两条直线的交点距离关系。题内定义仍由LLM按文字拆成基础关系，不能按名字硬编码。

## 更通用的备选：构造式点引用

将点引用允许为原名或受控选择器，例如：

```json
{"intersection":["AC","BD"]}
```

长度比、目标等可在点引用位置使用它，由代码建立对象。优点是任何需要交点的关系都能复用；缺点是同一选择器可能重复多次，JSON与schema比一个专门的通用关系更长。

建议常见关系优先直接表达，只在关系或所求确实需要一个独立对象时使用受控构造式引用。题目明确命名的点仍使用原名。不要恢复模型侧定义模板、形参、实例或前缀命名。
