本文保留 2026-09-15 的历史设计。2026-09-16 已改用 [数学字符串抽取契约](seven-problem-math-notation-review.md)，本地未提交的 `problem-domain/v2` 专用实现和分派已清理；本文中的 `prompt.py`、`contracts.py` 等链接描述历史实现，不再是当前代码入口。历史数据仍保留，生产 `solver/extraction` 接口未在本次切换。清理范围及验证见 [清理报告](validation/math-notation-legacy-cleanup-20260916/README.md)。更早的双树等方案保存在 [历史设计归档](validation/understanding-simplified-20260915/historical-designs.zip)。

## 1. 职责与边界

首轮多模态 LLM 只做两件事：从完整题图输出一份整题 IR；填写匹配题型，或明确 unmatched。识图包含理解并展开本题临时定义，但不求解，不生成答案，不设计运行时结构。

代码负责名称解析、基础关系转换、结构和量纲校验、修订、审计与安全展示。表达合法、匹配成功、Solver 就绪是三个独立结论。合法 IR 不以 Solver 投影成功为前提；匹配错误不能丢弃合法 IR 候选。

本步骤为独立试验入口，生产抽取入口仍用现有 `solver/extraction` 链。暂时两条入口只为阶段隔离，不是历史数据兼容层。当前没有用户，不要求兼容旧线上数据；本步骤不清空数据、不部署、不改公共 HTTP API 或数据库。

## 2. 整题契约

模型输出契约为 `problem-domain/v2`，恢复到 2026-08-10 `problem-domain/v1` 的 root/children 形状，按当前需要补齐关系及 unmatched；不是回退整个 Git 提交。

```json
{
  "schema_version": "problem-domain/v2",
  "family_id": null,
  "match_status": "unmatched",
  "match_reason": "当前注册的二次函数Solver不覆盖此题的通用几何条件和正切目标。",
  "root": {
    "label": "整题",
    "source_text": ["完整题干，包括题内定义。"],
    "entities": [],
    "facts": [],
    "goals": [],
    "children": [],
    "uncertainties": []
  }
}
```

这个片段说明形状；可执行合法示例由 [prompt.py](../server/shuxueshuo_server/problem_understanding/prompt.py) 和操作目录生成并经过真实解析器测试。

各层均使用 `label/source_text/entities/facts/goals/children/uncertainties`。一个题目只有一棵树，按文字上的小问和图景层级组织。不得再套 `transcription/domain/match` 三套对象，也不增加平行的 parts 树。

- `matched`：family 必须存在于服务端提供的 registry，填写匹配依据。
- `unmatched`：family 必须为 null，理由说明具体能力缺口，完整保留 IR。
- `entities`：point/scalar/curve 使用原名；point 仅按原文明确标记 fixed/moving，普通点省略 role；截线比例和对角线平分不要求模型命名辅助交点。
- 不确定项：missing_figure、ambiguous_symbol、unreadable、occluded、unstructured、ambiguous_reuse，附简短文本。
- problem_id、原图身份、内部 ID、精确 revision、registry 快照由服务端绑定。模型复制这些字段视为契约错误。
- 禁止模型输出 solver_projection、verified_problem、accepted 等执行或采用声明。

JSON 顶层合法时，IR 与匹配分别校验、分别保存报告。匹配错误仍可保留合法 IR。非法 JSON、重复键、非有限数、截断和尾随垃圾都不能通过截取片段“恢复成功”。

## 3. 基础关系与定义展开

单一操作目录位于 [contracts.py](../server/shuxueshuo_server/problem_understanding/contracts.py)，生成字段 schema 和 [操作表](validation/understanding-definition-fix-20260915/operations.md)。示例构造器也使用该目录；编译器分派只接受登记操作。

常见角度、长度、面积、中点、交点、平行、垂直、射线、坐标、曲线、最值直接用扁平 fact。比如：

```json
{"kind":"angle_equal","angles":["BAC","DAC"]}
```

```json
{"kind":"angle_ratio","angles":["BDC","ABD"],"ratio":["2","1"]}
```

`ratio:[u,v]` 表示按对象顺序第一个:第二个=u:v；编译为交叉相乘关系，不能随意颠倒比例。不将 ratio fact 当成除法目标。真正的面积比/长度比所求会记录分母非零义务。

几何简写 AB/ABC 只适用于已声明的单个大写字母点名；A1 等点名使用数组。线段无向，角为非定向内角且按度数解释，面积无向；多边形按 `polygon.vertices` 保留顶点顺序。射线保留起点与方向。交点的 interior 可省略，不能默认 true。

复杂表达式使用受控字符串，代码解析为内部 SymPy 节点，不使用 eval 或直接 sympify 模型字符串。支持精确有理数、根式、参数、加减乘除、有界整次幂，以及 length、angle、area、x、y、degrees、length_units、area_units、tan。数字/长度/面积/角度检查量纲；角度不能由无单位数字冒充。

题目临时定义的概念由模型按本题定义应用到各小问，输出基础 fact，保留定义原文。没有 KQuad 等运行时类型，没有按名称或题号分派的规则。定义中的未确定分支用通用 `any_of` 表示，每个分支是同时成立的 fact 列表。

本题的四个图景独立。AECD 的对角线为 AC、ED，可暂用局部名字 X 表示其交点，但不能据此断言它与 O 不同；由已知共线关系可确认它就是 O。校验器允许同一点参与多组交线，不在本轮加入自动几何身份合并。其余三图允许在明示平分条件下采用等价两分支，由有界比较验证。无法证明等价时保留差异；不根据缺失图片猜测条件。

## 4. 名称与作用域

模型每问继续写 A、B、k，不写 p1_A/p2_A 或命名空间。本层声明为本层局部对象，本层未声明才向父层查找；不会访问兄弟小问。局部同名声明可以遮蔽父层名字。显式跨问沿用而不能确定时，模型保留歧义；代码不能自动合并。

代码为实体、fact、goal 分配地址式 ID，只用于候选内部索引和定向 patch。不要要求模型设计这些 ID。代码也不要求逐句 source_unit_ids、覆盖表、定义形参或实例元数据。

## 5. 独立校验、修订与展示

独立校验器不导入 family registry 或 Solver，检查：schema、词法引用、对象类型、比例方向、量纲、明显退化、已知冲突、分母和正切定义域，以及资源上限。匹配校验单独接收 registry 中的 family 名单。

资源边界：子作用域深度最多 4；每个表达式 1,024 字符、256 AST 节点、32 深度，整数幂绝对值不超过 12；IR 运算输入和逻辑展开有总量限制，超过时报告错误，不截断原题条件。

不能证明的定义域条件记录为 `well_definedness_obligations`，不添加成题设，也不表示已证明可解。代码只查确定性一致性，不声称引用存在就证明理解与原图一致。

精确 revision 包含原始顺序与文字；语义比较支持原名替换、实体声明重排、对称关系交换、受支持的精确算式等价写法，以及有界 AND/OR 分组规范化。小问层级、比例方向、多边形顶点顺序、目标、逻辑分支和定义域义务的变化不能被抹掉。该比较是保守回归工具，不是任意几何定理证明器。

定向 patch 使用 `base_revision` 与代码分配的 unit_id，只替换授权实体/fact/goal；不提供修改原文、删除原文要求、修改不确定项或题型的通道。应用后重新校验。旧 revision、越界单元、重复修改及非法引用拒绝。

产物存储保留原始返回、服务端绑定、不可变候选、合法 IR、编译结果和分开的验证报告。HTML 只显示原题、基础条件、所求、待确认项和匹配声明，统一转义，不生成答案或推测图形。所有结果均为候选，source_reviewed=false，solver_ready=false。

## 6. 提示词和 OCR

提示词包含原图优先、完整 IR、字面层级和原名、可 unmatched、题内定义展开、受控表达式和 JSON 要求；使用独立“合邻三角形”定义 few-shot（60° 条件与两组 AND 条件构成的 OR 同时保留），另用短组织示例固定编号下两个图景、局部 k、cut_ratio 无需交点名及 role 的写法。不给模型转录树+领域树、不要求前缀命名、来源映射或模板。

OCR 服务仍运行，完整观察仍原样保存。新增辅助视图只给页序、文字分行、有效补充/不同公式候选和必要的中性提示：

- unknown 孤立行、漏检行、分式分母不能丢失；不按 layout/printed 命中裁掉文字。
- 不传逐行坐标、ID、置信度、内部诊断错误。
- 手写/混合行提示可能为批注；不提升为已确认题干。遮挡和笔迹按页提示。
- 仅删除同一来源位置的完全相同公式候选；不同候选保留并提示以原图为准。
- 原始观察哈希、来源状态和生产视觉复核触发策略不变。

尺寸以紧凑 JSON、ensure_ascii=False 的 Unicode 字符统计，不计图片 base64。当前测量与历史基线见 [measurements.json](validation/understanding-organization-fix-20260915/measurements.json)。必须分别比较 schema、OCR 辅助、示例、完整提示词和输出，不能以删题设压缩。

## 10. 组织规则修复（2026-09-15）

已明确：按题面编号组织子节点；编号内的独立图景继续分 children；原文只放直接所属节点，父节点无独立文字时填 []。独立图景分别声明对象与参数，仅题面明确共用时放父层。为表达必需的未命名交点可取未占用的局部名字并写 intersection；不同图景可重复使用该名字。role 只允许原文明示的 fixed/moving，不再让模型选择 given/constructed。

比较器先校验原始输入，再对同一层级内类型/role 相符的未匹配名字尝试有界配对，必须完整语义一致才通过；不把多个实体合成一个，也不跨兄弟小问匹配。移除“同一点被多组交线定义就一律报错”的规则：多条线本就可以共点。允许这种表达不意味着已经证明其与原图一致。

本轮只做离线回归，没有追加真实模型调用。新增快照和结果见 [组织规则修复验收](validation/understanding-organization-fix-20260915/README.md)，之前的单次真实失败记录保持不变。

## 12. 缺图必须返回用户处理（2026-09-15）

用户确认：暂不干预模型推理区重复编写 JSON，继续观察，不增加禁止预写 JSON 的提示词。已实施的 source_text 不跨层重复规则保持。

“如图”“图1”等文字仅是引用，模型必须核对图片中实际存在的图形。未提供时在对应层填 missing_figure 并指出所缺图形；保留可读条件和所求，不想象特殊四边形性质、点序或内部交点。

**只要候选标记缺图，就停止后续处理，等待用户补图。** 不再以“文字可能充分”作为继续的例外，也不因 matched/unmatched 改变阻断规则。缺图不等于 unsupported，不把已提取 IR 丢弃或冒充 schema 错误。

隔离候选服务现返回服务端计算的 continuation：status=needs_confirmation、blocked=true、error_code=extraction.missing_figure、user_action=supplement_image，并携带各层的缺图说明。IR/match 的 contract_valid 仍只表示契约合法，不能作为继续依据。continuation 独立保存，HTML 候选显示补图提示。没有缺图时仍为 candidate_only，不签发 Solver 就绪证明。

当前生产入口仍使用旧契约，本轮未接入生产 HTTP API 或前端；以上是必须落实的产品接入约束。独立 smoke 继续检验“缺图 IR 是否正确提取”，即使基准测试通过，continuation 仍明确阻断；没有后续求解阶段。
